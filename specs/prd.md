# PRD — 게시판 포털

> 2026-08-02 · 초안 Claude · 결정 사용자
>
> **미결 0건.** 남은 것은 기술 결정(DBMS · DB 접근 도구)이고 ADR 로 따로 간다.

---

## 1. 어떤 목적인가

**학습이다.** 게시판은 소재고, 배우고 남기는 것이 목적이다.

> **겉핥기로 아는 것보다 하나를 깊게 아는 것이 중요하다.
> 전부 다 하는 것보다 하나하나 늦어도 천천히 '이해'하는 것이 최우선이다.**

동시에 **완성도는 실무 수준으로** 간다. 실제로 쓰는 사람은 없지만, 대충 돌아가는 게 아니라
실무처럼 동작해야 한다.

**그래서 이 프로젝트는 두 축으로 판단한다.**


| 축       | 무엇                              |
| ------- | ------------------------------- |
| **이해**  | 왜 그렇게 만들었는지 설명할 수 있는가 ← **최우선** |
| **완성도** | 실무에서 통할 수준으로 동작하는가              |


---

## 2. 무엇이 문제인가

**만들 줄은 아는데 왜 그런지를 모른다.**

지금까지는 AI 가 시키는 대로 폴더를 나누고 기술을 골랐다. 나중에 *"이거 왜 이렇게 했어요"*
라는 질문에 **"AI 가 하라고 했어요"** 밖에 답할 수 없다.

**이 프로젝트는 그 대답을 없애기 위한 것이다.**

---

## 3. 누가 쓰나


|              | 누구     | 무엇을 하러 오나                            |
| ------------ | ------ | ------------------------------------ |
| **비로그인 방문자** | 아무나    | 공지·글·갤러리를 읽는다. 문의 목록도 본다             |
| **회원**       | 가입한 사람 | 글·댓글·문의를 쓴다. 자기 글을 고치고 지운다           |
| **관리자**      | 운영자    | 공지를 쓰고, 문의에 답하고, 분류를 관리하고, 남의 글을 지운다 |


학습 목적이므로 *"회원이 왜 가입하는가"* 는 따지지 않는다.

---

## 4. 목표와 성공 기준

**폴더 구조 하나, 기술 선택 하나까지 근거를 댈 수 있는 상태.**

### 어떻게 확인하나 — 이슈마다 질문 하나

**이슈를 닫기 전에 질문 하나에 답한다.** 답은 이슈의 `## 질문의 답` 칸에 남긴다.

- 질문은 **암기를 묻지 않는다.** *"방금 만든 것이 어떻게 도는지"* 를 묻는다
- 답이 막히면 그 지점이 다음에 배울 것이다
- 이슈에 답이 쌓인 것 자체가 **기록**이다 — 나중에 *"이거 왜 이렇게 했어요"* 의 답이 여기 있다

**답을 못 하면 이슈를 닫지 않는다.** 게이트다 — 자세한 것은 8장.

---

## 5. 기능 범위

**요구사항 문서에 있는 것이 범위다.** 어떻게 만들지는 여기 쓰지 않는다.

> ⚠️ **이 목록은 목표가 아니라 상한이다.** 8장이 우선한다 —
> 이해와 부딪히면 여기서 덜어낸다. 다 못 만들어도 실패가 아니다.

### 5.1 공통 — 게시판 4종 전부

- 목록을 **기간·분류·검색어**로 찾을 수 있다
- 목록의 **개수·정렬**을 바꿀 수 있고, 바꾸면 **바로 반영**된다
- 상세를 보고 목록으로 돌아오면 **찾던 조건이 그대로** 있다
- 최근에 올라온 글은 **새 글로 표시**된다
- 글을 쓰려면 로그인해야 한다. **자기 글만 고치고 지운다**

### 5.2 게시판별로 다른 것


|       | 공지사항      | 자유게시판   | 갤러리             | 문의게시판            |
| ----- | --------- | ------- | --------------- | ---------------- |
| 누가 쓰나 | **관리자만**  | 회원      | 회원              | 회원               |
| 분류    | O         | O       | O               | **없음**           |
| 첨부    | 없음        | 파일 여러 개 | **이미지 여러 장**    | 없음               |
| 댓글    | 없음        | **있음**  | 없음              | 없음               |
| 특별한 것 | **위에 고정** | —       | **모아 보기·넘겨 보기** | **비밀글 · 관리자 답변** |


### 5.3 메인

4개 게시판의 최근 글을 **한 화면**에서 본다. 각 영역에서 해당 게시판으로 들어간다.

### 5.4 계정

가입 · 로그인 · 로그아웃. **관리자 로그인은 일반 사용자와 입구가 다르다.**

### 5.5 관리자

게시판 4종을 관리하고, 문의에 답하고, **분류를 관리**한다.

*(분류 관리는 요구사항 문서에 화면이 없지만, 다른 화면들이 "관리자가 등록한 분류"를
참조하므로 만든다. 7장 우선순위 4번.)*

### 5.6 실험 — 첨부 부하 *(범위 안)*

**자유게시판에 무거운 파일을 여러 개 올려서 무슨 일이 생기는지 직접 본다.**

**언제**: 자유게시판(우선순위 2)을 **끝낸 뒤 마지막에**, 할 수 있는 만큼 밀어붙인다.

기능이 아니라 **학습 활동**이다. 만들고 끝내지 않고 **한계를 눈으로 보는 것**이 목적이라
1장(이해가 최우선)과 같은 방향이다.

---

## 6. 범위 밖

**지금 만들지 않는 것.**

- 비밀번호 찾기 · 이메일 인증 · 소셜 로그인
- 회원 정보 수정 · 탈퇴
- **관리자를 추가로 만드는 기능** — 초기 관리자 하나만 두고 시작한다
- 알림 · 검색 자동완성 · 좋아요 · 신고
- 다국어 · 모바일 앱

**관리자는 환경변수로 관리한다.** 화면으로 만들지 않는다.

⚠️ 알고 받는 대가: 환경변수는 **없을 때만** 계정을 만든다. 그래서
**비밀번호를 잊으면 환경변수를 바꿔도 안 바뀐다** — DB 에서 그 행을 직접 지워야 다시 만들어진다.
로컬 개발이라 DB 에 손댈 수 있으니 문제가 되지 않는다. 배포하면 다시 본다.

## 7. 우선순위


| 순서  | 무엇          | 왜 먼저인가                                         |
| --- | ----------- | ---------------------------------------------- |
| 1   | 계정(가입·로그인)  | 나머지 전부가 *"누가 썼는가"* 를 필요로 한다                    |
| 2   | 자유게시판       | **4종 중 제일 복잡하다**(댓글+첨부). 여기서 만든 공통 구조를 나머지가 쓴다 |
| 3   | 공지사항        | 2번 구조 재사용 + 고정                                 |
| 4   | 관리자 + 분류 관리 | 1~3 이 분류를 필요로 하는데 관리 화면이 없으면 손으로 넣어야 한다        |
| 5   | 갤러리         | 이미지 여러 장                                       |
| 6   | 문의게시판       | 비밀글·답변                                         |


**4번 유지 확정.** 2~3 단계에서는 분류 데이터를 손으로 넣고 간다.

## 8. ★ 이해가 완성도를 이긴다 — 확정

> ### **다 못 만들어도, 만든 것은 이해가 다 되어야 한다.**

**1장과 5장이 서로 당기는데, 부딪히면 이해 쪽을 남긴다.**


|     |                                              |
| --- | -------------------------------------------- |
| 1장  | *"전부 다 하는 것보다 하나하나 늦어도 천천히 **이해**하는 것이 최우선"* |
| 5장  | *"요구사항에 있는 것은 **전부** 만든다"*                   |


둘 다 지킬 수 있으면 좋지만, **시간이 부족해지면 반드시 부딪힌다.**
게시판 6개를 다 만들려고 서두르면 이해가 얕아지고, 하나를 깊게 파면 6개를 못 끝낸다.

### 이 결정이 실제로 바꾸는 것


|                |                                                   |
| -------------- | ------------------------------------------------- |
| **범위(5장)의 성격** | 목표가 아니라 **상한**이다. 다 못 만들어도 실패가 아니다                |
| **멈추는 기준**     | *"기능이 되는가"* 가 아니라 **"설명할 수 있는가"** 로 다음 단계에 간다     |
| **버리는 방향**     | 게시판 **개수**를 줄인다. 만든 게시판의 **깊이**를 줄이지 않는다          |
| **금지**         | 이해 못 한 채로 진도를 빼는 것. *"일단 되니까 넘어가자"* 가 이 프로젝트의 실패다 |


### 확인 장치 — 이슈마다 질문 하나가 **게이트**다

> ### **답을 못 하면 이슈를 닫지 않는다. 다음으로 넘어가지 않는다.**

*"나중에 보자"* 를 허용하지 않기 위해서다. 허용하면 **영원히**가 된다.

**막혔을 때 푸는 길**

```
답이 막힘 → 블로그를 읽는다 → 다시 답한다 → 그래도 막히면 Claude 가 설명한다
```

**막히는 것 자체는 실패가 아니다.** 그게 이 프로젝트가 찾으려는 지점이다.
실패는 **모르는 채로 넘어가는 것**이다.

⚠️ 이 규칙의 대가: **한 곳에서 막히면 진도가 선다.** 알고 받는다.
