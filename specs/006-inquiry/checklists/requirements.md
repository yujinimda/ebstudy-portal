## 이 체크리스트가 실제로 잡은 것 — **3건**

체크리스트가 아무것도 잡지 못하면 그것은 형식이다. 이번에 잡은 것을 먼저 적는다.

| # | 무엇 | 성질 | 조치 |
|---|---|---|---|
| 1 | **`FR-014`가 문서 자신과 어긋나 있었다** — 수정·삭제를 묶어 *"작성자 본인만"* 이라 적었는데 Edge Cases와 판단 16은 **관리자 삭제를 허용**한다 | **모순.** 계약이 어느 쪽으로 쓰든 한쪽 문장을 위반한다 | `FR-014` 문구 정정 + **`AC-51` 신설** |
| 2 | **비밀글 수정 시 빈 비밀번호의 처리에 AC가 없었다** | **누락.** 규칙은 Edge Cases에 있는데 **아무도 검증하지 않는다** → `AC-23`이 금지한 상태가 수정 경로로 우회 생성될 수 있다 | **`AC-49` 신설** |
| 3 | **`0000`의 유효성에 AC가 없었다** | **누락.** 숫자로 다루면 값의 공간이 1만보다 줄고 `SC-003`의 전제가 흔들린다 | **`AC-50` 신설** |

**셋 다 판정 기준은 하나였다** — 001의 5번 게이트가 세운 것 그대로다:

> **"Edge Cases에만 적혀 있고 AC가 없으면 커버리지 분모에 들어가지 않으므로 아무도 세지 않는다."**

001에서 이 기준이 `AC-35`·`AC-36`·`AC-37`을 만들어냈고, **006에서 같은 기준이 3건을 더
찾아냈다.** 게이트가 한 번 잡은 것이 규칙이 되어 다음 스토리에서 다시 값을 낸 사례다.

## Requirement Completeness

- [ ] **미확정 항목 0개 (3번 게이트 종료 조건)** — **미충족.**
  - `/speckit-clarify`를 **아직 돌리지 않았다.** `NEEDS CLARIFICATION` 마커는 없지만,
    **판단 18건(★ 보안 8건) · ADR 후보 7건 · 계획의 미해결 11건**이 사람 확인을 기다린다.
  - **마커가 없다는 것과 미확정이 없다는 것은 다르다.** 이 스펙은 미확정을 마커 대신
    **"판단한 것 — 사람 검증 필요" 표**로 모았고, 그 표가 비지 않았다.
  - → **3번 게이트 진입 전이며, 판단 표의 ★ 8건이 우선 확인 대상**이다.
- [x] **요구사항이 검증 가능하고 모호하지 않다** — AC 51개 전부 `Given/When/Then + AC-ID`.
      *"잘 동작한다"* 류의 문장 **0건**.
- [x] **모든 기능 요구사항에 대응하는 인수기준이 있다** — **AC 없는 FR 0건.**
      FR 36개 ↔ AC 51개 양방향 대조 완료(아래 매핑 확인).
- [x] 성공 기준이 측정 가능하다 — `SC-001`~`SC-009`. *"0건"* · *"100%"* · *"3번 이내"* 처럼
      셀 수 있는 형태다.
- [x] 성공 기준이 기술 중립적이다 — 기술 용어 없음.
      *(`SC-008`이 **"4자리라는 조건상 오프라인 전수조사는 막지 못한다"** 를 함께 적은 것은
      성공 기준의 한계를 감추지 않은 것이라 감점 대상이 아니다.)*
- [x] 모든 인수 시나리오가 정의되어 있다 — `AC-1`~`AC-51`, 스토리 4개에 배분.
- [~] **엣지 케이스가 식별되어 있다** — **식별은 충분하나 3건을 제외하면 AC가 없다**
  - 4범주 18항목(경계값 5 · 동시성 5 · 빈 값 6 · 권한 경계 6) + *"한계"* 2항목.
  - **AC로 올린 것**: `AC-49`(빈 비밀번호 수정) · `AC-50`(`0000`) · `AC-51`(관리자 삭제).
  - **AC로 올리지 않은 것**: `from > to` · 페이지 0·음수 · 빈 목록 200 · 마지막 페이지 너머 ·
    검색어 공백 · `secret=false` 인데 비밀번호를 보냄 · 조회수 동시 증가 유실 허용.
  - **기준**: 올린 셋은 **권한이 뒤집히거나 비밀 공간이 줄어드는** 것이고, 올리지 않은 것은
    **400/200 판정**이라 위험 등급이 다르다.
  - **대가를 명시한다**: 올리지 않은 항목은 **커버리지 게이트가 세지 않는다.**
    계약 문서가 오류 코드로 못박았고 배정 표가 통합 테스트 케이스로 붙였지만,
    **테스트 이름에 AC-ID가 없으면 빠져도 드러나지 않는다.**
    → **3번 게이트에서 사람이 "이 중 AC로 올릴 것이 있는가"를 판단한다.**
- [x] 범위가 명확히 경계 지어져 있다 — Out of Scope 11항목 + *"다른 스토리·단계가 정할 것"* 8항목.
- [x] 의존 관계와 가정이 식별되어 있다 — Assumptions 9건 · 001 의존 8건 · 판단 18건.

### 미해결로 남는 사항

- **`AC-12`(검색 조건 유지)의 테스트 레벨**이 공통 프론트(5단계)의 구현 방식에 종속된다.
  스펙은 **동작만** 규정하므로 스펙 결함은 아니지만, **레벨이 정해지기 전에는 배정이 잠정**이다.
- **프론트 단위 테스트 도구가 ADR 없이 정해져 있다**(001에서 이미 지적된 항목).
  `AC-12`·`AC-27`·`AC-48`의 단위 배정이 그 위에 얹힌다 — **006이 단독으로 정할 것이 아니다.**
- **게시판 공통 오류 코드 접두사**가 미정이라 `INQUIRY_` 는 잠정이다.
  바뀌면 **문자열만 일괄 치환**되고 AC 구조는 유지된다.
