# 잠금(lock) — "코드로 막으면 깨진다"의 메커니즘

## 물은 맥락

트랜잭션(어제) → 제약·외래키(오늘) 다음 개념으로 이어서 물었다.

3.5에서 사람이 **`username` 중복을 DB 제약에 맡긴** 판단의 근거가
*"코드로 막으면 동시 요청에서 깨진다"* 였고, `test-strategy.md` 5.2는
*"롤백만으로는 커밋이 일어나지 않으므로 동시성을 테스트할 수 없다"* 고 했다.
**두 문장이 같은 메커니즘을 가리키는데 그 메커니즘에 이름을 붙이지 않았다.**

관련 결정: `data-model.md`(유일 제약을 DB에) · `test-strategy.md` 5.2(격리 = 혼합) ·
`spec.md` Edge Cases(동시 가입 경합)
선행 노트: `2026-07-29-ddl-transaction.md`(트랜잭션) · `2026-07-29-index.md`(유일 인덱스) ·
`2026-07-29-foreign-key-constraint.md`(제약)

## 쉬운 말 요약

- **확인하고 실행하는 사이에 틈이 있고, 그 틈에 다른 요청이 끼어든다.** 코드로는 원리적으로 못 막는다.
- **잠금**은 **"내가 만지는 동안 기다려"** 다. **트랜잭션이 끝나면 풀린다.**
- 우리는 잠금을 **직접 안 쓰지만 UNIQUE 제약이 알아서 잠근다.** 그게 *"DB에 맡겼다"* 의 정체다.
- **판정이 커밋할 때 일어나서**, 롤백만 하는 테스트로는 이걸 확인할 수 없다.

## 설명

### 먼저 무엇이 깨지는가 — 우리 스펙의 실제 케이스

`spec.md` Edge Cases의 **동시 가입 경합**이다. 중복을 코드로 막으면 이렇게 된다.

```
시각  요청 A                      요청 B
 1    'kim' 있나? → 없다
 2                                'kim' 있나? → 없다      ← 둘 다 통과한다
 3    INSERT 'kim'  → 성공
 4                                INSERT 'kim'  → ???
```

**"확인"과 "실행" 사이에 틈이 있고 그 틈에 다른 요청이 끼어든다.**
이것을 **경합 조건(race condition)** 이라고 한다.

> **코드로 아무리 잘 확인해도 못 막는다.**
> **확인한 순간의 사실이 실행하는 순간에는 이미 거짓**일 수 있기 때문이다.
> 3.5의 판단이 옳았던 이유가 이것이고, 그 판단은 **동시 가입 경합 테스트로 검증된다.**

### 잠금 = "내가 이거 만지는 동안 너는 기다려"

도서관에 **마지막 한 권**이 남았고 두 사람이 동시에 빌리려 한다.
사서가 **한 명씩** 처리하면 — 한 명이 끝날 때까지 다른 사람은 기다린다 — 한 명만 빌리게 된다.

| | 뜻 | 비유 |
|---|---|---|
| **공유 잠금** (읽기) | 여러 명이 **동시에 읽어도 된다.** 단 쓰는 것은 막는다 | 여러 사람이 같은 책을 **같이 들여다보는** 것은 되지만 그동안 아무도 못 가져간다 |
| **배타 잠금** (쓰기) | **한 명만.** 읽기도 막는다 | 사서가 그 책을 **손에 들고 있는 동안** 아무도 못 만진다 |

### ★ 잠금은 트랜잭션이 끝날 때까지 유지된다

어제 배운 트랜잭션이 여기서 다시 나온다. **`COMMIT` 또는 `ROLLBACK`을 하면 풀린다.**

→ **트랜잭션을 길게 잡으면 다른 요청들이 그만큼 오래 기다린다.**
그래서 **트랜잭션 안에서 외부 API 호출이나 파일 업로드를 하지 않는다** — 응답이 느린 작업이
잠금을 붙잡고 있으면 그 사이 다른 요청이 전부 대기한다.

> `research.md` 6이 남용 방어의 지연을 **"트랜잭션 밖에서"** 하도록 정한 이유가 이것이다
> (5번 게이트에서 보강된 항목). 지연을 트랜잭션 안에서 하면 **일부러 넣은 4초 동안
> 잠금을 쥐고 있게 된다.**

### 우리는 잠금을 직접 쓰지 않는다 — 그러나 잠금 위에서 돈다

`UNIQUE` 제약에 맡겼고, **유일 인덱스가 삽입할 때 알아서 잠금을 잡는다.**

```
A: 인덱스에 'kim' 자리를 먼저 잡는다 → 그 자리에 잠금
B: 같은 자리를 잡으려 한다 → 기다린다        ← 잠금 대기

A가 COMMIT   → B는 "중복" 오류 (409, AC-10)
A가 ROLLBACK → B가 성공
```

**"DB에 맡겼다"의 정체가 이것이다.** 직접 잠그는 코드를 쓰지 않지만 잠금이 일하고 있다.

### 그래서 `test-strategy.md` 5.2의 문장이 이해된다

> 롤백만으로는 **커밋이 일어나지 않으므로 동시성을 테스트할 수 없다**

위 흐름에서 **판정이 `COMMIT` 시점에 일어난다.** 롤백만 하면 **그 판정 자체가 안 일어난다.**

→ 그래서 **동시 가입 경합 테스트만 예외적으로 "초기화 방식"** 을 쓴다.
3.9에서 격리 방식을 *"혼합"* 으로 정한 이유가 **이 테스트 하나**다.
그리고 `ADR-003`의 리스크 1(함수 유니크 인덱스를 `validate`가 검증하지 않는다) 때문에
**그 테스트에 `Kim` vs `kim` 경합을 넣기로** 했다 — 잠금이 **소문자로 바꾼 값의 자리**에서
걸리는지를 확인하는 것이다.

### 교착 상태(deadlock) — 대표적 함정

```
A: X를 잠그고 → Y를 원한다
B: Y를 잠그고 → X를 원한다
```

**둘이 영원히 서로를 기다린다.** DB가 감지해서 한쪽을 죽이고 오류를 낸다.

**예방법은 하나 — 항상 같은 순서로 잠근다.**
A도 B도 *"X 먼저, Y 나중"* 으로 하면 원리적으로 생기지 않는다.

**001에서는 발생하지 않는다** — 한 요청이 테이블 하나만 만진다.
**002에서 게시글 + 첨부파일을 함께 다루면 후보가 된다.**

### 비관적 / 낙관적 — 실무에서 쓰는 말

| | 태도 | 방법 |
|---|---|---|
| **비관적 잠금** | "충돌할 것이다" | **미리 잠근다.** `SELECT ... FOR UPDATE` |
| **낙관적 잠금** | "충돌 안 할 것이다" | 안 잠그고, **저장할 때 버전이 바뀌었는지 확인.** 바뀌었으면 실패시키고 재시도 |

**001에는 둘 다 필요 없다** — *"읽고 고쳐 쓰는"* 흐름이 없다.
JPA는 `@Version`으로 낙관적 잠금을 지원하지만 지금 쓸 자리가 없다.

### ★ 002에 하나 기다리고 있다 — 조회수 (`process.md` 8.3 미정 항목)

```
A: 조회수 읽는다 → 10
B: 조회수 읽는다 → 10
A: 11로 저장
B: 11로 저장      ← 조회가 2번인데 1만 올랐다
```

이것을 **갱신 유실(lost update)** 이라고 한다. **동시 가입 경합과 같은 모양의 문제**다 —
읽고 쓰는 사이에 틈이 있다.

| 대응 | 평가 |
|---|---|
| 낙관적 잠금(`@Version`) | 된다. 다만 실패 시 재시도 코드가 필요하다 |
| **원자적 증가**(`SET 조회수 = 조회수 + 1`) | **더 간단하다.** 읽지 않고 DB에게 "1 늘려라"라고 시킨다 — **틈이 없다** |

조회수에는 후자가 맞다. **002에서 정할 때 이 노트를 참조한다.**

### 인덱스와 같은 모양의 교환이다

| | 얻는 것 | 잃는 것 |
|---|---|---|
| 인덱스 | 읽기가 빨라진다 | **쓰기가 느려진다** |
| **잠금** | **정확성** | **동시 처리량** |

**잠금도 공짜가 아니다.** 안전과 속도를 교환하는 장치이며, 그래서 *"필요한 만큼만, 짧게"* 가 원칙이다.

### 한 장 정리

```
경합 조건  =  "확인"과 "실행" 사이의 틈에 다른 요청이 끼어드는 것
              → 코드로는 원리적으로 막을 수 없다

잠금       =  "내가 만지는 동안 기다려"
              공유(읽기, 여럿 가능) / 배타(쓰기, 한 명)
              트랜잭션이 끝날 때 풀린다  → 트랜잭션을 짧게

우리 방식   =  잠금을 직접 쓰지 않고 UNIQUE 제약에 맡긴다
              유일 인덱스가 자동으로 잠근다
              판정은 COMMIT 시점 → 그래서 롤백 격리로는 테스트할 수 없다

교착 상태   =  서로를 기다림. 예방 = 항상 같은 순서로 잠근다
갱신 유실   =  읽고 쓰는 사이의 틈. 002 조회수가 그 자리
```
