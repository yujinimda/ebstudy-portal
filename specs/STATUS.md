constitution 원칙 III: 실재하는 선택지가 둘 이상이면 사람이 확정한다.

**① 커버리지 목표** (`test-strategy.md` 5.3)

| | |
|---|---|
| A | 줄 커버리지 목표를 둔다 (예: 80%) |
| B | 목표 없음 |
| **C** | **AC 커버리지 100%** + 줄 커버리지는 참고 지표로만 ← **Claude 추천** |

C 추천 근거: 숫자 목표가 있으면 그 숫자를 채우려고 의미 없는 테스트를 쓴다.
그리고 통합 중심 전략에서는 한 요청이 여러 계층을 통과하므로 **줄 커버리지가 특히 부정확하다**
(90%인데 중요한 검증이 빠질 수 있고 60%인데 다 덮였을 수 있다).
우리는 AC-ID로 추적하므로 "모든 AC가 테스트를 갖는가"를 **정확히 셀 수 있고 그것이 의미 있다.**

**② E2E 도구** (`test-strategy.md` 5.4)

**Playwright 추천 (사실상 확정 상태)** — `test-strategy.md` 4장의 효율화 규칙 2번(로그인 상태
재사용)과 4번(자동 대기)이 이미 Playwright 기능을 전제로 적혀 있다. 바꾸면 그 규칙을 다시 써야 한다.

→ 두 개가 확정되면 `test-strategy.md` 5장을 결정 기록으로 바꾸고 6장 결정 이력에 추가,

## 협업 방식 (반드시 유지)

`process.md` 5.5에 규칙으로 있고, 실제로 지켜야 하는 것:

1. **판단 근거가 없는 영역에서 3지선다를 던지고 "당신 근거로 답하라"고 하면 작동하지 않는다.**
   → ① 실무가 어떻게 하는지 먼저 알려준다 ② Claude가 정하고 이유를 설명한다
   ③ "이 이유가 납득되나요, 걸리는 데가 있나요?"로 **검증을 요청한다**
2. **실재하는 대안을 빠뜨리면 그 자체가 위반이다** (constitution 1.1.0).
   사람은 제시된 목록 밖의 선택지를 볼 방법이 없다.
3. **작업 단위마다 커밋·PR·머지까지 끝낸 뒤 멈추고 사람이 읽을 시간을 준다.**
4. **재검증하지 않는다.** 1차 검증 지적을 반영하면 통과. 대신 **무엇을 어떻게 고쳤는지 기록**한다.
5. 개념은 **비유로 설명하면 잘 통했다** — 세션=클럽 팔찌, JWT=위조 불가 도장 찍힌 신분증,
   Refresh 저장=명단(장부).
6. 설명 후 **"아직 흐릿한 데 있나요?"** 로 확인한다. 실제로 여러 번 오해가 잡혔다.
