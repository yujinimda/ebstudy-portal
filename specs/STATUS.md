## 용어 — `001` 같은 번호가 무엇인가

*(2026-07-29 신설. 사용자가 **"001이 뭐야?"** 를 물어서 만들었다.
`001`은 남의 기술 용어가 아니라 **우리가 직접 만든 이름**인데 모든 문서가 설명 없이 쓰고 있었다.
`process.md` 5.5 규칙 0 위반 3번째 사례.)*

**`001`~`006`은 스토리 번호다.** 프로젝트를 **6조각**으로 쪼갰고 그 순서다.

```
001  인증           가입 · 로그인 · 로그아웃 · 권한        ← 지금 여기
002  자유게시판      목록 · 상세 · 등록 · 댓글 · 첨부 · 권한
003  공지사항        002 구조 재사용 + 상단고정
004  관리자 화면 + 카테고리 관리
005  갤러리          + 이미지 다수 · 캐러셀
006  문의게시판      + 비밀글 · 답변
```

**한 번호가 세 곳에 같이 붙는다.**

| | 001의 경우 |
|---|---|
| 브랜치명 | `001-user-auth` |
| 스펙 폴더 | `specs/001-user-auth/` |
| AC 번호 | `AC-1`~`AC-37` — **스토리 안에서 연속** |

**ADR 번호는 다르다** — `ADR-001`~`ADR-005`는 **스토리와 무관한 프로젝트 전역 연속 번호**다
(`process.md` 3장: *"ORM 선택은 001에서 결정했어도 002·003 전부에 적용된다"*).
**`001`과 `ADR-001`은 서로 관계가 없다.**

**왜 이렇게 쪼갰나 — 수직 슬라이스**: 층(전체 DB → 전체 API → 전체 화면)으로 쪼개면
**마지막까지 동작하는 것이 없어 9.5 기능 QA가 성립하지 않는다.**
기능 하나를 DB부터 화면까지 끝까지 만든다. → `process.md` 8.1

**왜 002가 자유게시판인가 — 어려운 것 먼저**: 가장 단순한 공지사항부터 하면
파일·댓글·권한을 003에서 처음 만나 001·002를 다시 뜯게 된다.
**재설계 비용이 뒤로 갈수록 커진다.** → `process.md` 8.1

```
✅  codex exec -s read-only "..."  < /dev/null   ← stdin 을 닫는다. 필수
❌  codex exec "..." | tail                      ← 파이프하지 않는다
```

- **`< /dev/null` 로 stdin을 닫지 않으면 무응답으로 멈춘다.** 실제로 **16분간** 출력 없이
  `Reading additional input from stdin...` 상태로 대기했다
- **`| tail` 등으로 파이프하면** 끝날 때까지 진행 상황이 전혀 보이지 않는다
- **`-s read-only`** 로 돌린다 — 검증자가 파일을 고치면 판정과 수정이 섞인다
- **5번에서는 문제없이 완주했다** (약 12분 · 185k 토큰)

## 협업 방식 (반드시 유지)

`process.md` 5.5에 규칙으로 있고, 실제로 지켜야 하는 것:

1. **판단 근거가 없는 영역에서 3지선다를 던지고 "당신 근거로 답하라"고 하면 작동하지 않는다.**
   → ① 실무가 어떻게 하는지 먼저 알려준다 ② Claude가 정하고 이유를 설명한다
   ③ "이 이유가 납득되나요, 걸리는 데가 있나요?"로 **검증을 요청한다**
2. **실재하는 대안을 빠뜨리면 그 자체가 위반이다** (constitution 1.1.0).
   사람은 제시된 목록 밖의 선택지를 볼 방법이 없다.
3. **작업 단위마다 커밋·PR·머지까지 끝낸 뒤 멈추고 사람이 읽을 시간을 준다.**
4. **재검증하지 않는다.** 1차 검증 지적을 반영하면 통과. 대신 **무엇을 어떻게 고쳤는지 기록**한다.
5. 개념은 **비유로 설명하면 잘 통했다** — 세션=클럽 팔찌, JWT=위조 불가 도장 찍힌 신분증,
   Refresh 저장=명단(장부).
6. 설명 후 **"아직 흐릿한 데 있나요?"** 로 확인한다. 실제로 여러 번 오해가 잡혔다.
7. **개념 설명 뒤에는 항상 쉬운 말 3~4줄 요약을 붙인다** *(2026-07-29 요청)*.
   대화와 learning 노트 **양쪽 모두**. 설명이 부족한 게 아니라 **길어서 남는 게 흐려지는** 문제다.
   비유 한 줄 + **우리 프로젝트에서 그게 무엇인지** 한 줄을 반드시 넣는다. → `process.md` 4.2
8. **다발성 작업은 백그라운드 워크트리 에이전트로 넘긴다** *(2026-07-29 요청)*.
   커밋 가능한 지점까지만 직접 하고 나머지를 넘긴 뒤 **한두 줄로 알리고 제어권을 돌려준다.**
   긴 침묵이 문제이고 결과물의 양이 문제가 아니다. **push·PR은 넘기되 ADR·노트의 사람 칸은
   에이전트가 채우지 않도록 못박는다.**
