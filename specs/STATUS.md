### ⚠️ codex 실행 시 주의 (겪은 것 — 아래 "운영 함정" 표와 같은 내용)

```
✅  codex exec "..."  < /dev/null        ← stdin 을 닫는다. 필수
❌  codex exec "..." | tail              ← 파이프하지 않는다
```

- **`< /dev/null` 로 stdin을 닫지 않으면 무응답으로 멈춘다.** 실제로 **16분간** 출력 없이
  `Reading additional input from stdin...` 상태로 대기했다
- **`| tail` 등으로 파이프하면** 끝날 때까지 진행 상황이 전혀 보이지 않는다

**5번 통과 후**: 6번 `/speckit-tasks` → 6.4 `/speckit-analyze` → 6.5 codex →

## 협업 방식 (반드시 유지)

`process.md` 5.5에 규칙으로 있고, 실제로 지켜야 하는 것:

1. **판단 근거가 없는 영역에서 3지선다를 던지고 "당신 근거로 답하라"고 하면 작동하지 않는다.**
   → ① 실무가 어떻게 하는지 먼저 알려준다 ② Claude가 정하고 이유를 설명한다
   ③ "이 이유가 납득되나요, 걸리는 데가 있나요?"로 **검증을 요청한다**
2. **실재하는 대안을 빠뜨리면 그 자체가 위반이다** (constitution 1.1.0).
   사람은 제시된 목록 밖의 선택지를 볼 방법이 없다.
3. **작업 단위마다 커밋·PR·머지까지 끝낸 뒤 멈추고 사람이 읽을 시간을 준다.**
4. **재검증하지 않는다.** 1차 검증 지적을 반영하면 통과. 대신 **무엇을 어떻게 고쳤는지 기록**한다.
5. 개념은 **비유로 설명하면 잘 통했다** — 세션=클럽 팔찌, JWT=위조 불가 도장 찍힌 신분증,
   Refresh 저장=명단(장부).
6. 설명 후 **"아직 흐릿한 데 있나요?"** 로 확인한다. 실제로 여러 번 오해가 잡혔다.
