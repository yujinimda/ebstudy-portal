# ADR-021 업로드 파일의 안전성 검증 범위와 이미지 메타데이터 처리

- **상태**: **제안 — 사람 확정 대기.** 배포 환경과 함께 결정
- **날짜**: 2026-07-31
- **관련**: `specs/002-free-board/spec.md` ADR 후보 7 · `AC-32`·`AC-33`·판단 18 ·
  `specs/005-gallery/spec.md` 후보 6 · `FR-035` · `process.md` 8.3
- **되돌리기 비용**: **중~상.** 메타데이터는 **소급 적용이 안 된다** —
  제거하지 않고 저장한 이미지는 나중에 규칙을 바꿔도 **이미 공개된 것**이다.
- **합친 후보**: 002 후보 7(안전성 검증) · 005 후보 6(메타데이터).
  둘 다 *"업로드된 바이트를 그대로 믿을 것인가"* 라는 하나의 축이다.

---

## 1. 안전성 검증 범위

현재 스펙: **확장자·크기·개수만 검사하고 내용은 검사하지 않는다.**
대신 **다운로드를 강제**해서(`Content-Disposition: attachment` + `nosniff`) 브라우저가
해석하지 못하게 한다(002 `AC-32`·`AC-33`).

| | |
|---|---|
| **검사 없음 + 다운로드 강제** — 현재 스펙 | 단순하다. **★ `zip` 내부는 검사 수단이 사실상 없다**(002 판단 18 · `process.md` 8.3) |
| **별도 출처(origin)에서 서빙** | 설령 해석되어도 우리 쿠키에 닿지 않는다. 도메인이 하나 늘고 `httpOnly` 쿠키 설계와 만난다 |
| **백신·샌드박스 연동** | 실제로 내용을 본다. **업로드가 동기에서 비동기로 바뀐다** — *"검사 중"* 상태가 생기고 화면 흐름과 데이터 상태가 함께 바뀐다 |
| **`zip` 허용 철회** | 검사할 수 없는 형식을 아예 받지 않는다. **요구사항이 `zip`을 명시했으므로 요구사항 변경이다** |

★ **`FR-035`(005 인라인 표시)가 002에 없던 표면을 만든다.**
갤러리는 그림이 화면에 떠야 하므로 `attachment`를 붙일 수 없다.
**`nosniff`가 필수**가 되고, 공통 첨부 기반이 `attachment`를 고정으로 끌고 오면 **005 `AC-8`이 깨진다.**

★ **`jpeg` 문제** — 002 `AC-44`·`FR-026`과 005 `FR-014`가 허용 확장자를 `jpg`·`gif`·`png`(+`zip`)로
적었다. **현실의 JPEG 파일 상당수가 `.jpeg`다.** 사용자가 정상 사진을 올렸는데 거부된다.
**스펙을 먼저 고쳐야 하는 항목**이며(002 미해결 4) 002·005 **양쪽을 같이** 고쳐야 한다.

## 2. 이미지 메타데이터(EXIF 등) 처리

| | |
|---|---|
| **위치 정보만 제거** | 안전하면서 회전 정보가 남는다. **무엇이 개인 식별 정보인지 목록을 유지**해야 한다 |
| **전부 제거** | 가장 단순하고 안전하다. **★ 회전 정보(Orientation)도 사라져 세로 사진이 눕는다** |
| **제거하지 않음** | 촬영 위치·기기·시각이 그대로 공개된다. 공개 게시판에서 받아들이기 어렵다 |

## 권고

- **안전성**: 현 스펙(다운로드 강제) 유지 + **`zip` 허용을 다시 확인한다.**
  검사할 수 없는 형식을 받는 것이 정말 요구인지 3번 게이트에서 묻는다.
- **메타데이터**: **전부 제거하되 회전을 먼저 적용해 굽는다**(회전을 픽셀에 반영한 뒤 메타데이터를
  버린다). 그러면 *"눕는다"* 와 *"위치가 샌다"* 를 둘 다 피한다.
  **다만 이것은 축소본 생성 시점과 묶인다** → `ADR-019`.

## 남은 리스크

1. **확장자만 보는 검사는 우회된다.** 002 `AC-33`이 *"내용이 HTML인데 확장자가 `.png`"* 를
   이미 AC로 두었다 — 그 방어는 **응답 헤더 하나에 전부 걸려 있다.** 헤더를 빠뜨린 경로 하나가
   저장형 XSS가 된다. → `ADR-018`에서 **응답을 우리가 만드는 안**을 고르는 것이 전제다.
2. **비동기 검사를 나중에 도입하면 업로드 흐름 전체가 바뀐다.** 지금 동기로 설계한 화면과 AC가
   그때 다시 쓰인다. 방아쇠: 악성 파일 사고 또는 외부 요구.
