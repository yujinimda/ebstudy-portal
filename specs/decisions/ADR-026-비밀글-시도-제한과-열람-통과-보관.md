# ADR-026 비밀글 시도 제한의 저장 위치와 열람 통과 상태의 보관 방식

- **상태**: **제안 — 사람 확정 대기** ★ 배포 형태와 함께 정해진다
- **날짜**: 2026-07-31
- **관련**: `specs/006-inquiry/spec.md` ADR 후보 2·3 · `FR-021`·`FR-023`·`FR-024` ·
  `AC-34`·`AC-35` · `ADR-001`(stateless JWT) · `ADR-025` · 001의 점진적 지연
- **되돌리기 비용**: **중~상.** 인프라 결정(001이 *"분산 공격은 인프라 몫"* 으로 남긴 지점)과 묶인다.
- **합친 후보**: 006 후보 2 · 3. **둘 다 "요청자를 어떻게 식별하고 그 상태를 어디에 두는가"** 라는
  하나의 축이고, **요청자 식별 방식이 두 결정에서 같아야 한다.**

---

## 맥락

`ADR-025`에서 값 공간이 1만(숫자 4자리)이면 **시도 제한이 사실상 유일한 방어선**이다.
그리고 비밀번호를 한 번 맞힌 뒤 **그 통과 상태를 어딘가에 들고 있어야** 상세를 볼 수 있다.

★ **비로그인 사용자도 비밀글을 열 수 있어야 한다**(목록 조회에 로그인이 필요 없다 — 요구사항 6.2).
따라서 **"요청자"를 로그인 사용자로 좁힐 수 없다.** 이것이 두 결정을 어렵게 만드는 핵심이다.

## 1. 시도 제한 — 실패 횟수를 어디에 두는가

| | |
|---|---|
| **서버 메모리** (001과 같은 방식: 메모리 + 1대 전제 + LRU 상한) | 빠르고 추가 인프라가 없다. **서버를 늘리는 순간 제한이 무력화**되고 재시작으로 초기화된다. 006 계획은 *"공격자가 재시작을 유발할 수 없으므로 허용 가능"* 으로 판정했다 |
| **DB** | 증설·재시작에 견딘다. **실패 요청마다 쓰기**가 생긴다(공격 트래픽이 곧 DB 쓰기다) |
| **외부 캐시(Redis 등)** | 증설에 견디고 빠르다. **인프라가 하나 는다** + 시크릿이 는다(원칙 VII) |

★ **001이 같은 문제를 이미 메모리로 풀었다.** *"그 판단을 재사용할 수 있는가"* 가 이 결정의 절반이다.
다만 001의 대상은 **로그인 지연**이고 여기는 **1만 가지 값의 전수조사 차단**이다 — 무게가 다르다.

## 2. "클라이언트"를 무엇으로 식별하는가

| | |
|---|---|
| 로그인 사용자 | **비로그인 열람이 가능해야 하므로 단독으로는 안 된다** |
| 요청 출처(IP) | 같은 회사에서 접속한 여러 사람이 한 명이 된다. 반대로 출처를 바꾸면 우회된다 |
| **글 단위 카운터**(누가 시도했든 이 글의 실패 횟수) | 우회가 어렵다. **대신 공격자가 남의 글을 잠글 수 있다**(서비스 거부) |
| 조합 | 현실적. 규칙이 복잡해지고 테스트가 어려워진다 |

★ 006 계획은 **글 단위 + 클라이언트 단위 둘 다**를 상태로 잡았다(`AC-34`·`AC-35`).
그 정의를 확정하는 것이 이 ADR이다.

## 3. 열람 통과 상태를 어떻게 들고 있는가

| | |
|---|---|
| **서버 보관(세션형)** | 확실하다. **`ADR-001`이 정한 stateless 전제가 부분적으로 깨진다** |
| **서명된 단기 쿠키/토큰** | stateless를 유지한다. **위조 방지와 만료를 우리가 설계**해야 한다. 006 계획의 권고 |
| 보관하지 않음(매번 입력) | 가장 단순하고 가장 불편하다. 새로고침마다 비밀번호를 친다 |

`FR-021`(*"서버가 검증한다"*)은 어느 쪽이든 만족해야 한다 —
**화면이 본문을 받아 놓고 가리기만 하는 구현**은 금지다.

## 결정하지 않으면 무엇이 막히는가

`AC-34`·`AC-35`(시도 제한)와 비밀글 상세 전체 흐름의 테스트를 쓸 수 없다.
006 계획이 *"테이블이 아닌 상태 2종"* 으로 분리해 두었으나 **저장 위치가 비어 있다.**

## 남은 리스크

1. **메모리를 고르면 서버를 늘리는 순간 조용히 무력화된다.** 오류가 나지 않으므로
   **아무도 모른다.** → 완화: 증설 시점을 방아쇠로 문서에 적고, 서버 대수 전제를 코드 주석이
   아니라 이 ADR에 남긴다.
2. **차단이 걸린 사용자에게 이유를 어떻게 알리는가.** 006이 `ADR-028`에서 다루는 것과 만난다 —
   삭제된 글에 들어온 사용자가 *"비밀번호가 틀렸다"* 를 보고 반복 시도하다 차단에 걸리면
   **원인을 영원히 알 수 없다.**
