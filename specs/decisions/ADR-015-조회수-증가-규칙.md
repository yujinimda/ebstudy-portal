# ADR-015 조회수 증가 규칙 — 단순 증가 · 관리 화면 제외

- **상태**: **제안 — 사람 확정 대기.** 결정은 사실상 되어 있고 **근거와 대가를 남기는 ADR**
- **날짜**: 2026-07-31
- **관련**: 요구사항 1.4 · 002 `FR-016`·`AC-28`·`AC-29` · 003 `FR-016`·`FR-017`·`AC-23` ·
  005 `FR-012`·`AC-15` · 006 `FR-036`
- **되돌리기 비용**: **중** — 중복 방지로 바꾸면 *"누가 언제 봤는지"* 를 저장해야 해서
  데이터가 늘고, **과거 조회수의 의미가 달라진다**(같은 숫자가 다른 것을 뜻하게 된다).
- **합친 후보**: 003 후보 3. 4종 공통 사안이다.

---

## 맥락 — 교차 검사가 잡은 것

요구사항 1.4가 *"증가 규칙은 기획에 없다 → 단순 증가로 하고 판단을 문서에 남긴다"* 로 적었고
002·005·006이 그대로 따랐다. **그런데 003만 예외를 하나 더 두었다.**

| | 상세 조회 | **관리 화면 조회** |
|---|---|---|
| 002 `FR-016` | 1 증가 | **언급 없음** |
| 003 `FR-016`·`FR-017` | 1 증가 | **증가 금지**(J9) |
| 005 `FR-012` | 증가 | **언급 없음** |
| 006 `FR-036` | 열람 성공 시에만 증가 | **언급 없음** |
| 004 (관리 화면 소유자) | — | **조회수를 한 번도 언급하지 않는다** |

**그대로 두면 같은 관리 동작이 게시판마다 다르게 동작한다** — 공지는 안 오르고 나머지는 오른다.
통합 단계의 판단은 **003이 옳고 나머지가 비었다**는 것이다.

## 검토한 대안

### A. 단순 증가 + 관리 화면 제외 — **권고**

- 상세를 열 때마다 1 증가. 같은 사람이 새로고침해도 증가한다.
- **관리자 관리 화면을 통한 조회에서는 증가하지 않는다** — 관리자가 검수·수정하려고 열 때마다
  오르면 **조회수가 독자 수 지표가 아니게 된다**(003 J9).
- **단점**: 새로고침으로 숫자를 부풀릴 수 있다. 조회수가 *"열린 횟수"* 이지 *"읽은 사람 수"* 가 아니다.

### B. 단순 증가만 (관리 화면 예외 없음)

- 규칙이 하나뿐이라 가장 단순하다. 002·005·006의 현재 문장 그대로다.
- **기각 사유**: 관리자가 목록을 훑기만 해도 숫자가 오른다. 게시판 4종을 관리자가
  매일 검수하는 운영에서 **조회수가 의미를 잃는 속도가 빠르다.**

### C. 중복 방지 (같은 사람의 반복 조회를 세지 않음)

- 숫자가 *"읽은 사람 수"* 에 가까워진다.
- **기각 사유**: **"같은 사람"을 정의할 수 없다.** 목록·상세 조회는 로그인이 필요 없어서
  (요구사항 1.3) 로그인 사용자로 좁힐 수 없고, 요청 출처로 세면 같은 회사에서 접속한
  여러 사람이 한 명이 된다. 게다가 **누가 무엇을 봤는지 저장**하게 되어
  개인정보가 늘고 원칙 V(로그·저장 최소화)와 부딪힌다.

## 동시성 — 이 결정에 딸린 필수 조건

002 `AC-29` · 003 `AC-23`이 **동시 조회에서 증가분이 유실되지 않을 것**을 요구한다.
`읽고 → 더하고 → 쓰기`를 애플리케이션에서 하면 두 요청이 같은 값을 읽어 하나가 사라진다.
→ **DB에서 원자적으로 증가**시켜야 하며, 이것은 대안 선택과 무관하게 성립해야 한다.

★ **003 계획이 잡은 것**: 공지 **수정**이 조회수를 되돌린다 — 전 컬럼 `UPDATE`가 나가면
수정 화면을 연 시점의 조회수가 다시 쓰인다. **`AC-23`이 조회 경로가 아니라 수정 경로로 깨진다.**
같은 함정이 002·005·006에도 있다.

## 남은 리스크

1. **관리 화면 제외를 어떻게 판정하는가.** 004 `FR-011`이 *"권한 외의 조건으로 예외를 열지
   말라"* 고 했다 — **요청 경로로 판정하면 일반 사용자가 흉내낼 수 있다.**
   조회수는 권한이 아니라 표시 문제라 같은 급은 아니지만, **판정 근거를 정해야 한다.**
2. 조회수는 정확한 회계가 필요한 값이 아니다(006 Edge Cases). 그럼에도 AC가 유실 금지를
   요구하므로 **AC와 실제 요구가 어긋나 있는지** 확인할 가치가 있다.
