# ADR-019 이미지 파생본(축소본)과 파일 수명 — 생성 시점 · 주소·캐시 · 삭제 · 원본 보관

- **상태**: **제안 — 사람 확정 대기.** `ADR-018` 직후에 결정한다
- **날짜**: 2026-07-31
- **관련**: `specs/005-gallery/spec.md` ADR 후보 2·3·4·7 · `AC-4`·`AC-5`·`AC-32`·`AC-36` ·
  `SC-008`(고아 파일 0건) · Assumptions 9
- **되돌리기 비용**: **상~최상** — 생성 시점을 바꾸면 **이미 저장된 모든 이미지를 다시 처리**해야
  하고, 원본을 버리는 선택은 **되돌릴 수 없다.**
- **합친 후보**: 005 후보 2·3·4·7. **005 스펙과 계획이 둘 다 "1·2·3은 묶어서 결정"을 권고했다.**
  따로 정하면 서로 모순되는 조합(예: 매 요청 생성 + 장기 캐시)이 나온다.

---

## 1. 축소본을 언제 만드는가

| | 장점 | 단점 |
|---|---|---|
| **업로드 시 미리 생성** | 조회가 항상 빠르다. 스키마에 축소본 키를 `NOT NULL`로 둘 수 있다 | `AC-24`의 요청 처리 시간에 **20장분 처리**가 더해진다. 실패하면 업로드 전체가 실패인가? |
| **첫 요청 시 생성 후 보관** | 업로드가 가볍다 | 첫 조회가 느리다. 축소본 키 컬럼이 **nullable**이 되고 *"아직 없음"* 상태가 생긴다 |
| **매 요청 생성(보관 없음)** | 저장 공간이 늘지 않는다. 고아 축소본이 없다 | 조회마다 CPU. **캐시 정책과 정면으로 부딪힌다** |

**스키마가 달라진다** — 축소본 키 컬럼의 NULL 허용 여부, 또는 컬럼 자체의 유무.

★ **005 설계의 축**: *"썸네일 컬럼을 두지 않는다"* — 썸네일은 **첫 번째 이미지**라는 규칙에서
파생되므로 별도 컬럼이 없고, 그래서 **`AC-32`의 끊긴 참조가 원리적으로 발생하지 않는다.**
축소본 **키** 컬럼을 두는 것과는 다른 이야기다. 혼동하지 않는다.

## 2. 이미지 주소와 캐시 정책

| | |
|---|---|
| **내용에 따라 변하는 불변 주소 + 장기 캐시** | 순서를 바꾸면 주소가 바뀌므로 `AC-36`(썸네일 갱신)이 자동으로 성립한다. **조건: 목록 응답 자체는 캐시하지 않는다** |
| **고정 주소 + 짧은 캐시 + 재검증** | 단순하다. 대신 `AC-5`(캐시 재사용)의 효과가 줄고 `AC-36`이 캐시 만료에 의존한다 |

**`AC-5`와 `AC-36`이 부딪히는 지점을 이 결정이 해소한다.**

## 3. 이미지 파일 삭제 방식

| | |
|---|---|
| **즉시 물리 삭제** | 단순하고 용량이 늘지 않는다. **복구가 원리적으로 불가능** |
| **표시 후 일괄 정리(배치)** | 실수 복구 여지가 있고 **`SC-008`(고아 파일 0건)을 실제로 보장할 수 있다** |

★ **005 계획의 지적**: *"보상 삭제만으로는 고아 0건이 보장되지 않는다."*
DB 트랜잭션은 롤백되는데 파일 삭제는 롤백되지 않는다(그 반대도 마찬가지다).
**정리 배치가 있어야 성립**하고, 그건 *"표시 후 일괄 정리"* 쪽의 장치다.
→ **`SC-008`을 유지하려면 사실상 후자를 골라야 한다.** 아니면 `SC-008`을 낮춰야 한다.

★ **`ADR-010`(게시물 삭제 방식)과 묶인다.** 글이 소프트 삭제면 파일도 남겨야 하고,
하드 삭제면 파일도 지워야 한다. **두 결정이 어긋나면 지워진 글의 이미지가 계속 접근 가능해진다.**

## 4. 원본 보관 여부

005 Assumptions 9가 *"상세 캐러셀이 원본을 쓴다"* 로 가정했다.
**"리사이즈 후 원본 폐기"를 고르면 그 가정이 뒤집히고** 캐러셀도 파생본을 쓰게 된다.
용량은 시간에 비례해 증가하므로(글 1,000건 × 평균 10장 ≈ **10GB** + 축소본) 언젠가 만날 결정이다.

## 결정하지 않으면 무엇이 막히는가

**1단계 마이그레이션의 이미지 테이블 컬럼**이 이 결정이다(축소본 키의 유무·NULL 허용).
**005는 마이그레이션을 추가할 수 없다** — 이미지 테이블이 공통 1단계에 들어가야 시작할 수 있다.

## 남은 리스크

1. **애니메이션 GIF**: 축소본은 첫 프레임으로 만든다(005). 원본은 움직이고 카드는 정지한다.
2. **픽셀 상한**: 1MB 안에서도 픽셀 수가 매우 큰 이미지가 가능하고, 축소 과정에서
   **메모리를 크게 쓴다**. 상한 값은 005 미해결 4로 열려 있다.
3. **회전 정보** — 메타데이터를 전부 제거하면 세로 사진이 눕는다 → `ADR-021`.
