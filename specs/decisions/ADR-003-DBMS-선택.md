# ADR-003 DBMS — PostgreSQL

- **상태**: 채택
- **날짜**: 2026-07-29
- **관련**: `specs/data-model.md`(논리 설계) / `specs/process.md` 4.7·6.1 / `ADR-002`(기본키 전략)
- **되돌리기 비용**: **최상** — 손으로 쓴 마이그레이션 SQL 전부, 컬럼 타입, 인덱스 정의,
그리고 **이미 쌓인 데이터의 이관**이 영향받는다

> **이 결정은 원래 미결정 목록에 없었다.**
> `process.md` 6장의 "스택 상세"가 *자바 버전 · 빌드도구 · ORM · 프론트 구성*만 열거하고
> **DBMS를 빠뜨렸다.** 그런데 `data-model.md`는 스스로 "논리 설계만, DBMS 무관"이라고 밝혔고
> 4.7은 물리 설계(컬럼 타입·인덱스·콜레이션)가 **DBMS 의존**이라고 했다.
> 즉 **DBMS 없이는 6.7 마이그레이션 SQL을 한 줄도 쓸 수 없는데** 목록에 없었다.
> `ADR-002`에서 UUID 대안을 빠뜨린 것과 **같은 종류의 누락**이다(constitution 1.1.0:
> 실재하는 선택지를 빠뜨리는 것 자체가 위반).

---

## 맥락

4번 기술 계획에 들어가면서 스택을 확정해야 했다. 6.7에서 **사람이 직접 마이그레이션 SQL을
작성**하기로 했으므로(`process.md` 4.7, constitution 원칙 VI) DBMS는 그 작업의 전제다.

배경 조건 두 가지가 이미 정해져 있었다:

1. **3.5에서 `username` UNIQUE 제약을 DB에 맡겼다.** *"코드로 막으면 동시 요청에서 깨진다"* 는
 판단이었고, `test-strategy.md` 5.2가 **동시 가입 경합 테스트로 그 판단을 검증**하기로 했다.
 → **"DB가 정말 막아주는가"에 대한 신뢰도가 이 결정의 축이 된다.**
2. **원 요구사항은 MySQL을 전제했다** — 관리자 비밀번호를 MySQL `SHA2()`로 저장하라는 항목이
 있었다. 다만 그 항목 자체는 `process.md` 8.2에서 이미 기각했다(빠른 해시 + 평문이 쿼리
 로그에 남음).

## 검토한 대안

### A. PostgreSQL — **채택**

- **장점**
  - **DDL이 트랜잭션 안에서 돈다.** 마이그레이션이 중간에 실패하면 **아무것도 적용되지 않은
  상태로 되돌아간다.** MySQL은 DDL이 암묵적 커밋이라 실패 시 **반쪽 적용 상태가 남는다.**
  → **손으로 SQL을 쓰는 이 프로젝트에서 가장 직접적인 이점이다**(4.7 + 4.11 롤백 원칙)
  - 제약·타입 검사가 엄격하다. 범위를 넘는 값·형식이 틀린 값을 **조용히 변환하지 않고 거부한다**
  - `username` 대소문자 무시를 **함수 유니크 인덱스(`LOWER(username)`)로 명시적으로** 표현한다
  → 규칙이 **스키마에 보인다**
  - `TIMESTAMPTZ`로 시간대 처리가 명확하다
  - Flyway · JPA(Hibernate) · Testcontainers 지원이 1급이다
- **단점**: 아래 "그래서 포기한 것" 참조

### B. MySQL

- **장점**
  - **원 요구사항이 전제한 DB**라 요구사항 문서와의 거리가 가깝다
  - 대소문자 무시가 **기본 콜레이션으로 공짜**다(`utf8mb4_0900_ai_ci`)
  - 국내 실무 점유율이 높아 회사에서 만날 확률이 크다.
  `**ADR-001`에서 "회사에서 JWT가 기본"이라는 근거가 Claude 추천을 이긴 선례가 있고,
  같은 논리가 여기서도 성립할 수 있었다** — 그래서 이 대안을 선택지로 명시해 물었다
- **기각 이유**
  - **DDL이 트랜잭션 밖에서 돈다** → 마이그레이션 실패 시 반쪽 상태. A안의 최대 장점이 없다
  - 대소문자 무시가 "공짜"인 것이 **곧 "어디서 그렇게 되는지 스키마에 안 보인다"** 는 뜻이다.
  콜레이션은 컬럼 정의에 묻혀 있어 리뷰에서 놓치기 쉽고, `**spec.md`의 명시적 요구사항이
  암묵적 DB 설정으로 사라진다**
  - 사용자가 회사 표준을 근거로 들지 않았다 → `ADR-001`의 논리가 발동하지 않았다

### C. MariaDB

- MySQL 호환 포크. 라이선스가 자유롭고 일부 기능이 앞선다
- **기각**: MySQL을 고를 이유는 *"실무에서 만난다"* 인데, 그 이유로 고른다면 **MySQL 자체를
써야 한다.** MariaDB는 MySQL의 장점(점유율)도 PostgreSQL의 장점(엄격함·트랜잭션 DDL)도
온전히 주지 않는다

### D. SQLite

- 파일 하나로 끝나 로컬 개발이 가장 간단하다
- **기각**: 동시 쓰기가 사실상 직렬화되고, `test-strategy.md` 5.1이 임베디드 DB를 기각한
이유(**실제 운영 DB와 다르면 "테스트는 초록인데 프로덕션에서 터진다"**)에 그대로 걸린다.
**로컬 우선으로 가더라도 로컬 DB는 실제 운영에 쓸 DB여야 한다** — 그것이 로컬 우선을
선택할 수 있었던 조건이다

## 그래서 포기한 것


| 포기한 것              | 내용                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------- |
| **원 요구사항과의 거리**    | 요구사항이 MySQL을 전제했으므로 SQL 표현이 달라진다. 다만 MySQL 관련 항목(`SHA2()`)은 8.2에서 이미 기각했으므로 실질 충돌은 없다    |
| **대소문자 무시의 공짜 처리** | MySQL이면 콜레이션으로 끝나는 것을 **함수 유니크 인덱스로 직접 만들어야 한다.** 손이 더 가지만 **규칙이 스키마에 보이는 것**을 그 값으로 받았다 |
| 국내 실무 점유율          | 회사에서 MySQL을 만날 가능성이 더 크다. **다만 SQL 표준·JPA 사용법의 대부분이 공통이라 전이 손실은 크지 않다**                  |


## 파생 규칙 (물리 설계, 6.7에서 적용)


|                    |                                                                                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 자동증가 기본키           | `BIGINT GENERATED ALWAYS AS IDENTITY` — `**ADR-002`의 논리 결정(자동증가 숫자)은 그대로 유지**되고 DDL 표기만 Postgres 형태가 된다. `ADR-002`의 `AUTO_INCREMENT`는 MySQL 문법 예시였다 |
| `username` 대소문자 무시 | `CREATE UNIQUE INDEX ... ON users (LOWER(username))`. `**CITEXT` 확장은 쓰지 않는다** — 확장 의존을 늘리면 Testcontainers 이미지와 이식성에 조건이 붙는다                         |
| 시각 컬럼              | `TIMESTAMPTZ`                                                                                                                                       |
| 식별자 표기             | `snake_case`. Postgres가 따옴표 없는 식별자를 소문자로 접으므로 관례와 일치한다                                                                                              |


→ **누적 미결정의 "`username` 대소문자 무시 구현 방법"이 이 ADR로 해소된다.**

## 남은 리스크

1. **함수 유니크 인덱스를 JPA가 자동으로 알지 못한다.** 엔티티에 `unique = true`만 걸면
 실제 DB 인덱스와 어긋날 수 있다. `ddl-auto=validate`(4.7)가 **컬럼 존재는 검증하지만
 함수 인덱스 일치는 검증하지 않는다.**
 → `**test-strategy.md` 5.2의 동시 가입 경합 테스트가 이 인덱스를 실제로 확인하는
 유일한 장치**가 된다. 그 테스트에 대소문자 다른 아이디(`Kim` vs `kim`) 경합을 포함한다.
2. **로컬·CI·(미래의) 운영에서 Postgres 버전이 갈라질 수 있다.** Testcontainers 이미지 태그와
 로컬 Docker Compose 이미지 태그를 **같은 값으로 고정**한다. 방아쇠가 당겨져 호스팅을
 정할 때 그 버전을 맞출 수 있는지 확인 항목에 넣는다.
