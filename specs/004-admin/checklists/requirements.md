## 4번 계획에서 추가로 발견한 것 — **명세가 스스로 알 수 없었던 항목**

> 이 절은 001 체크리스트에 없던 칸이다. 004는 **구현이 병렬로 진행된 상태에서 스펙을 썼고**,
> 스펙을 쓰는 쪽에서 그 결과를 볼 수 없었다. 계획이 대조하며 드러난 것을 여기 적는다.

- [ ] ❌ **명세의 값이 이미 적용된 스키마와 일치한다** — **미충족 3건**

  | # | 명세 | 실제 스키마 | 조치 |
  |---|---|---|---|
  | 1 | `FR-016`·`AC-21` 이름 **1~30자** | `name VARCHAR(50)` | 사람 결정 (`plan.md` 미해결 3) |
  | 2 | Edge Cases *"표시 순서 음수 허용"* | `CHECK (sort_order >= 0)` | 사람 결정 (`plan.md` 미해결 4) — **지금 상태로는 명세가 허용한 입력이 500을 만든다** |
  | 3 | `FR-016` *"1자 이상"* | `CHECK (btrim(name) <> '')` | **명세를 고친다** — 공백만으로 이루어진 이름은 화면에서 빈칸으로 보인다. **DB가 옳다** |

- [x] **명세의 핵심 판단이 스키마와 일치한다** — `J-2`·`J-3`·`J-7`·`AC-18`·`AC-20`·`AC-34`가
      전부 이미 적용된 제약·인덱스와 맞는다(`plan.md` 0.1 대조표).
      **특히 `J-3`(사용 중 분류 삭제 금지)은 `ON DELETE RESTRICT`로 DB에 이미 박혀 있다**
- [x] **ADR 후보가 실재하는 대안을 빠뜨리지 않았다** (원칙 III — *"AI가 실재하는 대안을
      빠뜨리면 그 자체가 위반"*) — **`ADR-009`**가 세 안을 비교했고, 5가 두 안을 비교했다.
      **계획이 6번째 후보(프론트 테스트 레벨)를 신설했다** — 스펙이 *"E2E 8개"* 를 경고로만
      적고 **해소책을 대안으로 제시하지 않았기 때문**이다

## 매핑 확인 (FR → AC)

**스펙 본문의 매핑 표를 그대로 재확인했다. AC 없는 FR 0개.**

| FR 범위 | 대응 AC | 확인 |
|---|---|---|
| FR-001 ~ FR-005 (셸·접근) | AC-1 ~ AC-6 | ✅ |
| FR-006 ~ FR-008 (확인 절차·목록 규칙) | AC-7 ~ AC-11 | ✅ |
| FR-009 ~ FR-012 (삭제 예외·기록) | AC-12 ~ AC-16 | ✅ **`FR-011`이 짝 AC 2개**(AC-14·15)를 갖는다 |

| FR-025 ~ FR-027 (사용불가 아이디) | AC-33 ~ AC-35 | ✅ |

> **`FR` 번호에 `FR-028`이 분류 절 끝에 있고 사용불가 아이디 절이 `FR-025`~`FR-027`이다.**
> 번호가 주제 순서와 어긋나지만 **고치지 않는다** — 번호는 참조 키이고, 지금 다시 매기면

### 태스크 분해(6번) 시 주의

- **짝 AC 4쌍을 반드시 두 테스트로 나눈다** — `AC-12`↔`AC-14` · `AC-13`↔`AC-15` ·
  `AC-22`↔`AC-23` · `AC-26`↔`AC-27`. **한 테스트에 뭉치면 "예외가 새는가" 쪽이 조용히 빠진다**
- **`AC-28`은 두 응답을 서로 비교하는 테스트**여야 한다. 각각 200이어도 내용이 같으면 거짓이다
- **`AC-24`는 `test-strategy.md` 5.2의 초기화 격리 예외**를 쓴다. 롤백 격리로는 커밋 경합이
  일어나지 않아 **테스트가 항상 통과한다**
- **`AC-31`은 초기 데이터(V10) 때문에 조용히 통과할 수 있다.** 분류를 전부 비활성으로 내린

- **`AC-32`는 인증 쿠키 없는 클라이언트로** 돌린다. E2E는 `storageState`를 주입하므로
