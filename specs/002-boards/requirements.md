## 1. 공통 규칙 — 게시판 4종 전부

### 1.1 목록

| 요소 | 규칙 |
|---|---|
| 기간 검색 | 등록일시 `from ~ to`. **기본 1달**, **최대 1년까지만** 검색 가능 |
| 분류 | 관리자가 등록한 해당 게시판 카테고리 목록. `전체 분류` 포함 |
| 검색어 | 위 표의 범위. 부분 일치 |
| 개씩 보기 | **기본 10** · 20 · 30 · 40 · 50 |
| 정렬 기준 | **기본 등록일시** · 분류 · 제목 · 조회수 |
| 정렬 방향 | **기본 내림차순** · 오름차순 |
| 즉시 적용 | **개씩 보기·정렬은 선택 즉시 반영**한다(검색 버튼을 누르지 않는다) |
| 페이징 | `<<` `<` 1~10 `>` `>>` |
| 글 번호 | **전체 게시글 수 기준 역순**(행 번호가 아니다) |
| `new` 아이콘 | **생성 후 7일 이내**. 게시판별로 다를 수 있게 설정 가능해야 한다 |
| 검색조건 유지 | 상세→목록, 등록/수정 취소→목록 시 **직전 검색조건을 유지**한다 |

### 1.2 등록 / 수정

| 요소 | 규칙 |
|---|---|
| 제목 | 필수 · **100자 미만** |
| 내용 | 필수 · **4000자 미만** |
| 검증 | **서버에서 한다.** 화면 검증은 편의일 뿐이다(001 `FR-002` 와 같은 원칙) |
| 취소 | `"작성을 취소하시겠습니까?"` 확인 후 목록으로(검색조건 유지) |
| 등록/수정 | 관리자 화면은 `"정말로 수정/등록 하시겠습니까?"` 확인 후 진행 |
| 삭제 | `"정말로 삭제 하시겠습니까"` 확인 후 |

### 1.3 권한

| 동작 | 누가 |
|---|---|
| 목록·상세 조회 | **누구나**(문의게시판 비밀글 제외) |
| 글 등록 | 로그인 사용자(공지사항은 관리자만) |
| 글 수정·삭제 | **본인 글만.** 버튼도 본인에게만 보이되 **서버가 검증한다** |
| 댓글 삭제 | 본인 댓글만. **관리자는 모든 댓글 삭제 가능** |
| 미로그인 상태로 글 등록 시도 | 로그인 화면으로 → **로그인 후 바로 글 등록 화면으로** |

> ★ 001 `FR-019` · `AC-26` 이 그대로 적용된다. **화면에서 버튼을 숨기는 것은 권한 검증이
> 아니다.** 모든 수정·삭제는 서버가 소유자를 확인한다.

### 1.4 조회수

상세 조회 시 증가한다. 증가 규칙(같은 사람 중복 카운트 여부)은 기획에 없다 →
**단순 증가**로 구현하고 이 판단을 문서에 남긴다.

## 2. 메인 페이지

## 3. 공지사항 (003)

### 3.1 목록
- 공통 규칙 1.1
- **알림글(상단 고정)** — 관리자가 지정한 글은 **모든 페이지의 제일 상단**에 배경색으로 구분해 노출
- 상단 고정은 **최대 5개**. 5개를 넘게 등록하면 **최신 5개만** 사용자에게 노출
- 고정된 글은 **번호 대신 분류명(`알림`)** 을 보여준다

### 3.2 상세
분류 · 제목 · 등록일 · 등록한 관리자 이름 · 조회수 · 내용 · `목록` 버튼

### 3.3 관리 (관리자)
- 목록 + `글 등록` 버튼
- 등록/수정: 분류 · 제목 · 내용 · **상단 고정 체크박스**
- 삭제

## 4. 자유게시판 (002)

### 4.1 목록
- 공통 규칙 1.1
- 컬럼: 번호 · 분류 · 제목(**댓글 수** · `new` · **첨부 아이콘**) · 조회 · 등록일시 · 등록자
- `글 등록` 버튼

### 4.2 상세
- 분류 · 제목 · 등록일시 · 등록자 · 조회수 · 내용
- **첨부파일 다운로드** — 이미지 파일이라도 **다운로드로 처리**한다(인라인 표시 금지)
- **댓글**
  - 입력은 **로그인한 사용자만** 보인다
  - 목록은 누구나 본다. 작성자 이름 · 작성일시 · 내용
  - 삭제 버튼은 **본인 댓글에만** 보이고 **서버가 검증**한다
- `목록` · `수정`(본인만) · `삭제`(본인만)

### 4.3 등록/수정
- 분류(필수) · 제목(필수 100자 미만) · 내용(필수 4000자 미만)
- **첨부**: `jpg` `gif` `png` `zip` 만 · **개당 2MB 까지** · **최대 5개**
  - **서버가 검증한다**(확장자·크기·개수)
  - 수정 시 이미 올린 파일 다운로드 가능 · 개별 삭제 가능

## 6. 문의게시판 (006)

### 6.1 목록
- 공통 규칙 1.1 (**분류 없음**)
- **`나의 문의내역만 보기` 체크박스**
  - **로그인 시에만 보인다**
  - 내가 쓴 문의만 필터링. **다른 검색조건과 AND**
- 컬럼: 번호 · 제목(**답변완료/미답변** · `new` · **비밀글 자물쇠**) · 조회 · 등록일시 · 등록자

### 6.2 비밀글
- 등록 시 **비밀글 체크박스**
- 비밀글은 **잠금 비밀번호 4자리**를 설정한다
- 비밀글 상세 진입 시 **비밀번호 입력 화면**으로
- **본인이 작성한 글이면 비밀번호 입력을 건너뛴다**
- 목록 조회 자체는 **로그인이 필요 없다**

### 6.3 상세
- 제목 · 등록일시 · 등록자 · 조회수 · 내용 · **답변완료 / 미답변** 표기
- **관리자 답변** 영역 — 답변이 없으면 `"아직 등록된 답변이 없습니다."`
- `목록` · `수정`(본인 + **미답변일 때만**) · `삭제`(본인 + **미답변일 때만**)

### 6.4 등록/수정
- 제목(필수 100자 미만) · 내용(필수 4000자 미만) · **비밀글 체크박스**

### 6.5 관리 (관리자)
- 목록 (분류 없음)
- 상세에서 **답변 입력**(필수 4000자 미만) → `답변완료` 버튼
- `"답변 하시겠습니까?"` 확인 후 진행
- 삭제

## 8. 기획서와 다르게 가는 것 — **의도적 이탈**

기획서에 적혀 있으나 **001 에서 이미 다르게 결정한 것**들이다. 되돌리지 않는다.

| # | 기획서 | 우리 구현 | 왜 |
|---|---|---|---|
| 1 | Access-token 을 **LocalStorage** 로 관리 | **httpOnly 쿠키** | `ADR-001` · `AC-7`. LocalStorage 는 XSS 로 읽힌다 |
| 2 | Access-token **만료 시간 없음** | 사용자 30분 / 관리자 15분 + Refresh | 만료 없는 토큰은 유출 시 회수 수단이 없다 |
| 3 | 관리자 비밀번호를 **MySQL SHA2 함수**로 암호화 | **bcrypt**(`ADR-005` 는 Argon2id) | SHA2 는 빠른 해시라 비밀번호에 부적합 |
| 4 | 관리자 **세션** 30분 | **JWT**(세션 없음) | `ADR-001` — Stateless |
| 5 | 관리자 **MPA** / 사용자 **SPA** | **Next.js 하나**, 경로로 분리 | 4번 계획 사용자 결정. `FR-032` 는 경로 분리로 충족 |
| 6 | 아이디 4~12자 · 비밀번호 4~12자 · 이름 2~5자 | 아이디 4~11 · 비밀번호 8~64 · 이름 2~50 | `spec.md` `FR-003` 등. 이미 `README.md` 6절에 보고됨 |

## 9. 구현 순서와 병렬 경계

**공유 기반은 순차, 게시판별은 병렬.**

```
1. 데이터 모델 + 마이그레이션 V5~V9      ← 단일. 모든 것이 여기 의존
2. 공통 백엔드 기반 (검색·페이징·첨부)     ← 단일
3. 게시판 4종 백엔드                     ← 병렬 4
4. 관리자 API + 카테고리                  ← 병렬 (3과 겹치지 않음)
5. 프론트 공통(목록 훅·페이징·검색바)      ← 단일
6. 게시판 4종 프론트 + 관리자 화면         ← 병렬 5
7. 통합 검증                             ← 단일
```

**병렬 에이전트의 파일 경계 규칙**

| 담당 | 만져도 되는 곳 |
|---|---|
| 게시판 X 백엔드 | `backend/src/main/java/com/ebstudy/portal/<board>/**` 만 |
| 게시판 X 프론트 | `frontend/app/<board>/**` · `frontend/components/<board>/**` 만 |
| 공통 | 1·2·5 단계에서만. 이후 아무도 수정하지 않는다 |

**절대 금지**: 마이그레이션 파일 추가(1단계에서 전부 만든다) · `common/` 수정 ·
`build.gradle.kts` 수정 · 남의 패키지 수정.

> ⚠️ **`common/` 수정 금지가 실제로 부딪힌다** — **오류 코드는 `common/ErrorCode`에 모인다.**
> 002 혼자 22개를 추가해야 하고 003·005·006도 각자 추가한다.
> **병렬 레인 4개가 같은 파일을 고치게 되어 경계 규칙이 성립하지 않는다.**
> → **`ADR-030`** 이 이 충돌을 다룬다(권고: 2단계에서 4종의 코드를 한 번에 넣는다).
