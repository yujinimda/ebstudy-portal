# API 계약 — 001 인증

> `/speckit-plan` Phase 1 산출물. **AC와 1:1로 대응시킨 계약**이며,
> 7번에서 코덱스가 **이 문서와 `spec.md`만 보고** 테스트를 작성한다(구현 코드를 보지 않는다).

**공통 오류 형식**: RFC 9457 Problem Details + `code`/`traceId` 확장 (`process.md` 4.8)

```json
HTTP 4xx/5xx
Content-Type: application/problem+json
{
  "type": "/errors/<범주>",
  "title": "...",
  "status": 400,
  "detail": "사람이 읽는 메시지",
  "instance": "/api/users",
  "code": "USER_ID_LENGTH_INVALID",
  "traceId": "a3f9c2",
  "errors": [{ "field": "username", "reason": "길이 오류" }]
}
```

**자격증명 전달**: 전부 **`httpOnly` 쿠키**. **응답 본문에 토큰 문자열을 담지 않는다**(`FR-013`·`AC-1`).

| 쿠키 | 담는 것 | 수명 |
|---|---|---|
| Access | JWT (서명만 검증, DB 안 봄) | 사용자 30분 / 관리자 15분 |
| Refresh | **256비트 랜덤 문자열** (DB에 SHA-256 해시로 보관) | 사용자 14일 / 관리자 1일 |

**오리진**: 브라우저는 항상 프론트 오리진의 `/api/*`를 호출한다.
Next.js rewrite가 백엔드로 넘긴다 → **CORS 설정이 없다**(research.md 2).

## 1. `POST /api/auth/signup` — 회원가입

**인증**: 불필요

```json
{ "username": "newuser01", "password": "Study1234abcd", "name": "홍길동" }
```

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **201** | 성공. 권한은 `USER` | — | `AC-8` |
| 409 | 아이디 중복 (**대소문자 무시**) | `USER_ID_DUPLICATED` | `AC-10` |
| 400 | 아이디 4자 미만 또는 12자 이상 | `USER_ID_LENGTH_INVALID` | `AC-11` |
| 400 | 아이디에 허용되지 않은 문자 | `USER_ID_FORMAT_INVALID` | `AC-12` |
| 400 | 사용불가 아이디 (**대소문자 무시**) | `USER_ID_NOT_ALLOWED` | `AC-13` |
| 400 | 비밀번호 8자 미만 또는 64자 초과 | `USER_PASSWORD_LENGTH_INVALID` | `AC-14`·`AC-15` |
| 400 | 비밀번호가 아이디 문자열을 포함 | `USER_PASSWORD_CONTAINS_ID` | `AC-16` |
| 400 | 같은 문자 3회 이상 연속 | `USER_PASSWORD_REPEATED_CHAR` | `AC-17` |
| 400 | 이름 2자 미만 또는 50자 초과 | `USER_NAME_LENGTH_INVALID` | `AC-18` |

**계약 주의**

- **`AC-19`** — 위 400 응답들은 **화면을 거치지 않은 직접 호출에도 동일**해야 한다.
  화면 검증은 편의일 뿐 **서버가 방어선**이다(`FR-002`)
- **비밀번호 앞뒤 공백을 제거하지 않는다.** 비밀번호의 일부일 수 있다(Edge Cases)
- 길이는 **문자 수**로 센다. 한글·이모지 허용
- **동시 가입 경합**: 같은 아이디로 두 요청이 동시에 오면 하나만 201, 다른 하나는
  409 `USER_ID_DUPLICATED`. **DB 유니크 제약이 판정한다**(코드로 막으면 깨진다 — 3.5 판단)

## 2. `GET /api/auth/check-id?username=<값>` — 중복확인

**인증**: 불필요

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| 200 | `{ "available": true \| false }` | — | `AC-20` |
| **429** | 분당 10회 초과 (**클라이언트 단위**) | `CHECK_ID_TOO_MANY_REQUESTS` | `AC-30` |

**`AC-20`**: 여기서 `available: false`인 아이디는 **가입에서도 반드시 409**여야 한다.
중복확인을 통과했는데 가입이 실패하면 사용자가 원인을 알 수 없다.

> **이 엔드포인트는 설계상 아이디 존재 여부를 그대로 알려준다.**
> 그래서 빈도 제한이 **필수**다 — 없으면 `AC-3`으로 막은 계정 열거가 이 경로로 뚫린다.

## 3. `POST /api/auth/login` — 사용자 로그인

**인증**: 불필요

```json
{ "username": "hong01", "password": "Study1234abcd" }
```

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **200** | 성공. **쿠키 2개 설정. 본문에 토큰 없음** | — | `AC-1` |
| **401** | 비밀번호 틀림 | `AUTH_INVALID_CREDENTIALS` | `AC-2` |
| **401** | 아이디 없음 — **`AC-2`와 완전히 동일** | `AUTH_INVALID_CREDENTIALS` | `AC-3` |
| 429 | 같은 계정 실패 6회 이상 | `AUTH_TOO_MANY_ATTEMPTS` | `AC-29` |

### ★ 이 계약의 가장 깨지기 쉬운 부분

**`AC-2`·`AC-3`·`AC-32`의 응답이 상태코드·`code`·`detail` 메시지까지 모두 같아야 한다.**

메시지: `"아이디 또는 비밀번호를 확인해 주세요"`

- 하나라도 다르면 **아이디 존재 여부를 알아내 가입자 명단을 뽑을 수 있다**(계정 열거)
- 세 경로는 **서로 다른 예외**에서 나오기 쉽다 → 핸들러가 다르게 잡을 위험이 크다
- **그래서 각각 검증하는 테스트만으로는 부족하고, 세 응답을 서로 비교하는 테스트를 따로 둔다**

**점진적 지연** (`AC-29` · research.md 6): 1~2회 지연 없음 → 3회 1초 → 4회 2초 → 5회 4초 →
6회 이상 429 + 60초 차단. 윈도 15분, **성공 시 즉시 초기화. 계정은 잠기지 않는다.**

## 4. `POST /api/admin/auth/login` — 관리자 로그인 (**별도 진입점**)

**인증**: 불필요. **경로가 사용자와 다르다**(`FR-032`)

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **200** | `ADMIN` 계정 성공. **수명이 사용자보다 짧다** | — | `AC-31`·`AC-33` |
| **401** | `USER` 계정이 **정확한 비밀번호로** 시도 | `AUTH_INVALID_CREDENTIALS` | `AC-32` |
| 401 | 비밀번호 틀림 / 아이디 없음 | `AUTH_INVALID_CREDENTIALS` | |

> **`"관리자 권한이 없습니다"` 로 답하면 안 된다.**
> 그 아이디가 **존재하고 일반 사용자라는 것**을 알려주게 되어, `AC-3`으로 막은 계정 열거가
> 이 경로로 새 나간다. **실패는 전부 같은 얼굴이어야 한다**(`FR-034`).
>
> 403이 아니라 **401**인 것도 같은 이유다. 403은 "인증은 됐고 권한이 없다"를 뜻하므로
> 계정이 존재한다는 사실을 노출한다.

## 5. `POST /api/auth/refresh` — 재발급

**인증**: Refresh 쿠키

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| 200 | 유효. **새 Access 쿠키 설정** | — | `AC-4` |
| **401** | 로그아웃되어 무효화됨. **쿠키 삭제** | `AUTH_REFRESH_INVALID` | `AC-5` |
| 401 | 만료됨 | `AUTH_REFRESH_EXPIRED` | `AC-6` |

**`AC-4`는 사용자가 개입하지 않는다**(`FR-016`) — Access가 만료되면 재발급이 일어나
원래 요청이 성공해야 하고, 사용자는 재로그인을 요구받지 않는다.

**무효화와 만료의 `code`가 다르다** — 전자는 로그아웃, 후자는 시간 경과다.
사용자에게 보여줄 안내가 다르므로 구분한다. *(계정 존재 여부와 무관하므로
`AC-2`/`AC-3` 통일 원칙과 충돌하지 않는다 — 이미 인증된 티켓에 대한 응답이다.)*

## 6. `POST /api/auth/logout` — 로그아웃

**인증**: Access 또는 Refresh 쿠키

| 응답 | 조건 | AC |
|---|---|---|
| 204 | **해당 Refresh만 무효화 + 쿠키 삭제** | `AC-5` |

- **요청한 기기만** 종료한다(Assumptions 4). 다른 기기의 티켓은 유효하다
- **이미 발급된 Access는 만료까지 유효하다**(Edge Cases). 재발급이 막히므로
  최대 Access 수명(30분/15분)만큼 뒤에 완전히 차단된다.
  → 즉시 차단이 필요해지면 `ADR-001`을 대체하는 새 결정이 필요하다

## 7. `GET /api/me` — 로그인한 사용자 정보

**인증**: 필요

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| 200 | `{ "username": "...", "name": "...", "role": "USER" }` | — | `AC-4` 검증 대상 |
| 401 | 미인증 | `AUTH_REQUIRED` | |

## 8. `GET /api/admin/me` — 관리자 전용

**인증**: 필요 + **`ADMIN` 권한**

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **401** | 미인증 | `AUTH_REQUIRED` | `AC-21` |
| **403** | `USER` 권한 | `AUTH_FORBIDDEN` | `AC-22`·`AC-26` |
| **200** | `ADMIN` 권한 | — | `AC-23` |

**`AC-26`은 `AC-22`와 같은 요청이지만 다른 관점**이다 — *화면에서 버튼을 숨긴 것이
권한 검증이 아니다*를 확인한다. **테스트를 따로 둔다**(원칙 II: 여러 AC를 한 테스트로 뭉치지 않는다).

## 모든 응답에 걸리는 계약

| | 요구 | AC |
|---|---|---|
| `traceId` | **모든 오류 응답**에 포함되고, 같은 요청의 로그를 그 값으로 찾을 수 있다 | `AC-27` |
| 5xx | 일반 안내 메시지 + `traceId`만. **예외 메시지·스택·테이블명·컬럼명·제약조건명 금지** | `AC-28` |
| 로그 | 비밀번호·토큰을 **로그에도 남기지 않는다** | `FR-026` |

**`AC-28`이 막는 실제 사고**: 스프링 기본 동작에 맡기면
`Duplicate entry 'kim' for key 'user.uk_user_username'` 이 그대로 나가 **테이블명·인덱스명 +
"이 아이디는 이미 가입돼 있다"** 를 함께 알려준다. `AC-10`의 409는 **우리가 의도한 응답**이고,
이것은 **예기치 못한 예외가 새는 것**이라 다르다.

## 프론트 계약 (화면이 책임지는 것)

| | 요구 | AC |
|---|---|---|
| 쿠키 접근 불가 | 스크립트로 자격증명 쿠키를 읽을 수 없다 | `AC-7` |
| 목적지 복귀 | 미인증으로 인증 필요 화면 진입 → 로그인 후 **원래 화면**으로(홈이 아니다) | `AC-24` |
| **목적지 검증** | **외부 주소를 목적지로 넘기면 그 주소로 이동하지 않는다.** 같은 출처의 상대 경로만 허용 | **`AC-34`** |

> **`AC-34`의 검증 위치가 화면인 것은 `FR-002`·`FR-019`의 예외가 아니다.**
> 그 두 요구사항은 **입력 검증**과 **권한 검증**을 서버에서 하라는 것이다.
> 목적지 이동은 **브라우저가 수행하는 행위**이므로 막는 자리도 브라우저 쪽이다 —
> 서버는 이동에 관여하지 않으므로 서버에서 막을 대상 자체가 없다.
