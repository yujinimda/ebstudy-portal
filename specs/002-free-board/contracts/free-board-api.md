# API 계약 — 002 자유게시판

> `/speckit-plan` Phase 1 산출물. **AC와 1:1로 대응시킨 계약**이며,
> 7번에서 테스트를 쓰는 주체가 **이 문서와 `spec.md`만 보고** 테스트를 작성한다
> (구현 코드를 보지 않는다). 001 `contracts/auth-api.md`와 같은 규약을 따른다.

**공통 오류 형식**: RFC 9457 Problem Details + `code`/`traceId` 확장 — **001이 만든 것을
그대로 쓴다**(`process.md` 4.8 · 001 `FR-024`). 002는 **오류 코드만 추가**한다.

```json
HTTP 4xx/5xx
Content-Type: application/problem+json
{
  "type": "/errors/validation",
  "title": "Validation Failed",
  "status": 400,
  "detail": "검색 기간은 최대 1년까지입니다",
  "instance": "/api/boards/free/posts",
  "code": "BOARD_SEARCH_PERIOD_TOO_LONG",
  "traceId": "a3f9c2"
}
```

**인증**: 001의 `httpOnly` 쿠키(Access/Refresh). **002는 새 인증 수단을 만들지 않는다.**

**경로 규약**: `/api/boards/<board>/…`. **`<board>` 자리만 바꾸면 003·005·006이 그대로
쓰는 형태**다(`SC-009`). 게시판마다 다른 경로 모양을 쓰면 프론트의 목록 훅도 네 벌이 된다.

## 엔드포인트 요약 — 권한을 여기서 한눈에 본다

| # | 메서드 · 경로 | 인증 | 권한 | AC |
|---|---|---|---|---|
| 1 | `GET /api/boards/free/posts` | **불필요** | 누구나 | `AC-1`~`AC-26` |
| 2 | `GET /api/boards/free/categories` | **불필요** | 누구나 | `AC-18` `AC-42` |
| 3 | `GET /api/boards/free/posts/{postId}` | **불필요** | 누구나 | `AC-27`~`AC-31` `AC-59` `AC-63` |
| 4 | `GET /api/boards/free/posts/{postId}/attachments/{attachmentId}` | **불필요** | 누구나 | `AC-32`~`AC-35` `AC-55` |
| 5 | `POST /api/boards/free/posts` | **필요** | 로그인 사용자 | `AC-36`~`AC-49` |
| 6 | `PUT /api/boards/free/posts/{postId}` | **필요** | **작성자 본인만** | `AC-51`~`AC-56` `AC-61` |
| 7 | `DELETE /api/boards/free/posts/{postId}` | **필요** | **작성자 본인만** | `AC-57`~`AC-60` |
| 8 | `POST /api/boards/free/posts/{postId}/comments` | **필요** | 로그인 사용자 | `AC-64`~`AC-66` `AC-70` |
| 9 | `DELETE /api/boards/free/posts/{postId}/comments/{commentId}` | **필요** | **본인 또는 `ADMIN`** | `AC-67`~`AC-69` |

> **★ 6·7과 9의 권한이 다른 것이 의도다.** 글 수정·삭제에는 **관리자 예외가 없고**(`AC-54`),
> 댓글 삭제에만 있다(`AC-69`). 한 줄로 뭉뚱그려 *"본인 또는 관리자"* 라고 쓰면
> **`AC-54`가 조용히 깨진다.** 관리자의 **타인 글 삭제**는 004의 별도 경로다.

> **1~4가 인증 불필요인 것도 계약이다**(`FR-017`·`SC-001`). 보안 설정이 게시판 경로를
> 통째로 막으면 `AC-26`·`AC-31`·`AC-63`이 한꺼번에 깨진다 — **세 AC가 같은 한 줄에 걸려 있다.**

## 오류 코드 — **이 표가 단일 진실이다**

001과 같은 규약: 각 AC의 테스트는 **상태코드가 아니라 `code`를 단언**한다.
상태코드만 보면 아래 400 여덟 종이 서로 구분되지 않는다.

|---|---|---|---|

| `BOARD_PAGE_SIZE_NOT_ALLOWED` | 400 | 개씩보기가 10·20·30·40·50이 아님 | `AC-6` |
| `BOARD_SORT_NOT_ALLOWED` | 400 | 정렬 기준·방향이 허용목록 밖 | `AC-9` |
| `BOARD_CATEGORY_NOT_FOUND` | 400 | **검색 조건**의 분류가 없음 | `AC-18` |
| `POST_NOT_FOUND` | 404 | 글이 없거나 삭제됨 | `AC-30` `AC-59` `AC-70` |
| `POST_TITLE_REQUIRED` | 400 | 제목 미전송 또는 **공백만** | `AC-40` |

| `ATTACHMENT_EXTENSION_NOT_ALLOWED` | 400 | `jpg`·`gif`·`png`·`zip` 밖 (확장자 없음 포함) | `AC-44` |

| `COMMENT_NOT_DELETABLE` | **403** | 타인의 댓글 (**`ADMIN`은 제외**) | `AC-68` |
| `COMMENT_NOT_FOUND` | 404 | 댓글이 없거나 **그 글에 속하지 않음** | *(계약이 신설 — 아래 주)* |

**001에서 그대로 쓰는 것**: `AUTH_REQUIRED`(401) · `AUTH_FORBIDDEN`(403) ·
`INTERNAL_ERROR`(5xx). **002가 다시 정의하지 않는다.**

> **`COMMENT_NOT_FOUND`는 스펙에 없다** *(Claude 판단 — 사람 검증 필요)*.
> `AC-67`~`AC-69`가 *"있는 댓글"* 만 다뤄 **없는 댓글을 지우려 할 때의 응답이 비어 있다.**
> `FR-018`(*"존재하지 않거나 삭제된 글·첨부·**댓글**에 대한 요청은 404와 동일한 응답"*)이
> 그 자리를 이미 요구하므로 **FR에는 근거가 있고 AC만 없다.**
> → **`AC-72` 신설이 필요한지 3번 게이트에서 판단한다.** 지금은 계약에만 적어 둔다.

> ⚠️ **`code`를 뭉치지 않는다.** 위 400 여덟 종을 공통 코드 하나로 던지면
> 상태코드가 같아서 **테스트가 통과해 버린다.** 이것이 이 계약에서 가장 흔한 실패 방식이다
> → 아래 「가장 깨지기 쉬운 부분」 1번.

## 1. `GET /api/boards/free/posts` — 목록

**인증**: 불필요 (`AC-26`)

### 요청 파라미터

| 이름 | 필수 | 기본값 | 허용 | AC |
|---|---|---|---|---|
| `from` · `to` | 아니오 | **`to`=오늘, `from`=`to`−1개월** | 간격 **최대 1년** · `from ≤ to` | `AC-1` `AC-2` `AC-3` `AC-4` |
| `categoryId` | 아니오 | 없음 = **전체 분류** | 자유게시판에 **존재하는** 분류 | `AC-18` |
| `keyword` | 아니오 | 없음 | **빈 문자열·공백만 = 조건 없음** | `AC-15` `AC-16` `AC-17` |
| `page` | 아니오 | `0` | 0 이상 | `AC-12` `AC-13` |
| `size` | 아니오 | `10` | **10 · 20 · 30 · 40 · 50** | `AC-5` `AC-6` |
| `sort` | 아니오 | `CREATED_AT` | `CREATED_AT` · `CATEGORY` · `TITLE` · `VIEW_COUNT` | `AC-7` `AC-9` |
| `direction` | 아니오 | `DESC` | `DESC` · `ASC` | `AC-8` `AC-9` |

- **`from`·`to`는 날짜(연-월-일)로 받고 서버가 시각으로 확장한다** — `from`은 **당일 00:00:00**,
  `to`는 **당일 23:59:59.999**. `to`를 00:00으로 해석하면 *"오늘까지"* 검색에서
  **오늘 쓴 글이 안 나온다**(`AC-2`).
- **허용목록 위반은 보정이 아니라 거부**다(`FR-044`). `size=7`을 10으로 깎지 않는다.

### 200 응답

```json
{
  "items": [
    {
      "id": 1042,
      "number": 15,
      "categoryId": 4, "categoryName": "잡담",
      "title": "여행 다녀왔습니다",
      "commentCount": 3,
      "hasAttachment": true,
      "new": true,
      "viewCount": 27,
      "createdAt": "2026-07-28T14:03:11+09:00",
      "authorName": "홍길동"
    }
  ],
  "totalElements": 25,
  "totalPages": 3,
  "page": 1,
  "size": 10,
  "appliedCriteria": {
    "from": "2026-06-30", "to": "2026-07-30",
    "categoryId": null, "keyword": null,
    "size": 10, "sort": "CREATED_AT", "direction": "DESC"
  }
}
```

| 필드 | 계약 | AC |
|---|---|---|
| `number` | **결과 총건수 기준 역순 순번.** 페이지마다 1부터 다시 시작하지 않는다. 총 25건·`size=10`·`page=1`이면 첫 행 **15**, 마지막 행 **6** | `AC-14` |
| `commentCount` · `hasAttachment` | **행마다 따로 조회하지 않는다** — 목록 전체를 **한 번에** 집계한다 | `AC-21` `AC-22` `AC-71` |
| `new` | **서버가 판정한 값.** 화면이 `createdAt`으로 다시 계산하지 않는다 | `AC-19` `AC-20` |
| `authorName` | **이름만.** 작성자의 계정 식별자(아이디)를 담지 않는다 | `AC-27`과 같은 원칙 |
| `totalElements` · `totalPages` · `page` | 화면이 `<< < 1~10 > >>` 를 구성하는 근거 | `AC-12` |
| **`appliedCriteria`** | **서버가 적용한 조건을 그대로 돌려준다.** 기본값이 화면에도 있으면 두 곳이 어긋난다 | `AC-1` |

- **결과 없음** → **200 · `items: []` · `totalElements: 0` · `totalPages: 0`** (404가 아니다) — `AC-25`
- **범위를 넘은 페이지**(`page=99`) → **200 · 빈 목록 · 총건수는 그대로** (400이 아니다) — `AC-13`

### 오류

| 상태 | `code` | AC |
|---|---|---|
| 400 | `BOARD_SEARCH_PERIOD_TOO_LONG` | `AC-3` |
| 400 | `BOARD_SEARCH_PERIOD_INVALID` | `AC-4` |
| 400 | `BOARD_PAGE_SIZE_NOT_ALLOWED` | `AC-6` |
| 400 | `BOARD_SORT_NOT_ALLOWED` | `AC-9` |
| 400 | `BOARD_CATEGORY_NOT_FOUND` | `AC-18` |

### 계약 주의

- **정렬은 결정적이어야 한다**(`AC-10`). 정렬 값이 같은 행들의 순서가 요청마다 달라지면
  **페이지 사이에 중복과 누락**이 생긴다. 조회수 정렬은 **동률(0)이 기본 상태**다.
  → **모든 정렬 뒤에 `id`가 붙는다.** 이것은 구현 선택이 아니라 **계약**이다.
- **검색어의 `%`·`_`는 글자 그대로**다(`AC-16`). `%` 한 글자로 기간 내 전체 조회가 되면
  `AC-3`으로 세운 상한이 새 나간다.
- **검색어에 최소 길이 제한을 두지 않는다**(판단 17). 1자 검색이 허용된다.

## 3. `GET /api/boards/free/posts/{postId}` — 상세

**인증**: 불필요 (`AC-31`)

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **200** | 성공. **조회수가 1 증가한 값**이 담긴다 | — | `AC-27` `AC-28` |
| **404** | 없는 글 · **삭제된 글 — 응답이 완전히 같다** | `POST_NOT_FOUND` | `AC-30` `AC-59` |

```json
{
  "id": 1042,
  "categoryId": 4, "categoryName": "잡담",
  "title": "여행 다녀왔습니다", "content": "…",
  "authorName": "홍길동",
  "createdAt": "2026-07-28T14:03:11+09:00",
  "viewCount": 28,
  "owner": true,
  "attachments": [ { "id": 88, "originalName": "보고서 최종(1).zip", "sizeBytes": 1048576 } ],
  "comments": [ { "id": 501, "authorName": "김철수", "content": "좋네요", "createdAt": "…", "deletable": true } ]
}
```

| 필드 | 계약 | AC |
|---|---|---|
| **없는 필드** | 작성자의 **아이디·비밀번호 등 계정 정보** · 첨부의 **저장 경로·내부 파일명** | `AC-27` `AC-35` |
| `attachments[].originalName` | **올린 이름 그대로** | `AC-35` |
| `comments` | **작성일시 오름차순**(오래된 것부터). 목록의 기본 정렬과 반대다 | `AC-65` |
| `owner` · `comments[].deletable` | **화면이 버튼을 그릴지 정하는 힌트일 뿐 권한 판정이 아니다.** 서버는 6·7·9에서 다시 확인한다 | `AC-53` `AC-68` |

### 계약 주의

- **조회수는 동시 요청에서 유실되지 않아야 한다**(`AC-29`). *"읽어서 +1 해서 쓴다"* 로 만들면
  두 요청이 같은 값을 읽어 **증가가 덮어써진다.** 상세 조회는 **동시성이 예외가 아니라 일상**이다.
- **같은 사람이 다시 열어도 증가한다**(판단 6 — 중복 방지 없음).
- **비로그인도 200이고 댓글 목록이 담긴다**(`AC-63`). 화면만 입력 수단을 감추고,
  **서버는 8번에서 막는다** — 둘이 한 쌍이어야 성립한다.

## 4. `GET /api/boards/free/posts/{postId}/attachments/{attachmentId}` — 첨부 다운로드

**인증**: 불필요 (글이 공개이므로 첨부도 공개다)

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **200** | 파일 바이트 + **아래 헤더 4종** | — | `AC-32` `AC-33` `AC-35` `AC-55` |
| **404** | 첨부가 없거나 **그 글에 속하지 않음** | `ATTACHMENT_NOT_FOUND` | `AC-34` |
| 404 | 글이 없거나 삭제됨 | `POST_NOT_FOUND` | `AC-59` |

### ★ 응답 헤더 4종 — **한 세트다. 하나라도 빠지면 방어가 뚫린다**

| 헤더 | 값 | 없으면 |
|---|---|---|
| `Content-Disposition` | **`attachment`** | 브라우저가 페이지 안에 렌더한다 → **저장형 XSS** (`AC-32`) |
| `Content-Disposition`의 파일명 | **`filename*=UTF-8''…`(퍼센트 인코딩) + ASCII 대체 `filename=`** | 한글·공백·괄호가 든 이름이 **깨지거나 헤더가 잘린다** (`AC-35`) |
| `X-Content-Type-Options` | **`nosniff`** | 지정이 있어도 **브라우저가 내용을 보고 형식을 다시 판단**할 수 있다 (`AC-33`) |
| `Content-Type` | **서버가 확장자에서 정한 값** | **업로드 때 클라이언트가 보낸 값을 그대로 실으면** 위조된 타입으로 해석된다 |

> **이것은 편의가 아니라 보안 요구다.** 우리 출처에서 사용자 업로드 파일이 해석되면
> 그 스크립트는 **`httpOnly` 쿠키를 읽지 않고도 그 사용자 권한으로 요청을 보낼 수 있어**
> 001 `AC-7`이 세운 방어가 무의미해진다. **`zip`을 허용하는 이 게시판은 특히 위험하다** —
> 압축 내용은 검사할 수단이 사실상 없다(판단 18).

## 5. `POST /api/boards/free/posts` — 글 등록

**인증**: **필요** (`AC-37`) · **권한**: 로그인 사용자

**요청**: `multipart/form-data`

| 파트 | 필수 | 규칙 |
|---|---|---|
| `categoryId` | ✅ | 자유게시판의 **활성** 분류 |
| `title` | ✅ | **1자 이상 100자 미만** · 공백만 금지 |
| `content` | ✅ | **1자 이상 4000자 미만** · 공백만 금지 |
| `files` | — | **최대 5개** · 개당 **2MB 이하** · `jpg`·`gif`·`png`·`zip` |

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **201** | 성공. **등록자는 인증 주체** · 조회수 0 | — | `AC-36` |
| 401 | 미인증 | `AUTH_REQUIRED` | `AC-37` |
| 400 | 제목·내용·분류·첨부 위반 | 위 코드 표 | `AC-38`~`AC-47` |

### 계약 주의

- **등록자를 요청 본문에서 받지 않는다.** 본문으로 받으면 남의 이름으로 글을 쓸 수 있다(`AC-36`).
  요청에 `authorId` 같은 필드가 있으면 **무시가 아니라 계약 위반**이다.
- **`AC-48`** — 위 400들은 **화면을 거치지 않은 직접 호출에도 동일**해야 한다.
  파일 검증은 화면에서 하기 쉬워(`accept` 속성·크기 확인) **서버 검증을 빼먹기 가장 쉬운 자리**다.
  `test-strategy.md` 3장에 따라 **참조하는 `AC-38`~`AC-47` 각각에 따로** 테스트를 만든다.
- **경계는 포함/미포함까지 계약이다** — 제목 **99자 통과 / 100자 거부**, 내용 **3999 / 4000**,
  첨부 **정확히 2MB 통과 / +1B 거부**, 개수 **5 통과 / 6 거부**.
- **전부 성공하거나 전부 실패한다**(`AC-49`). 세 번째 파일 저장이 실패하면
  **글도 앞의 두 첨부 기록도 남지 않는다.**
- **미인증 401을 받은 화면은 로그인 후 원래 목적지로 돌아간다** — 001 `FR-020`·`FR-035`를
  그대로 쓴다. **목적지는 같은 출처의 상대 경로만**이며 **002가 새 규칙을 만들지 않는다.**

## 6. `PUT /api/boards/free/posts/{postId}` — 글 수정

**인증**: **필요** · **권한**: **작성자 본인만.** **`ADMIN`도 불가**(`AC-54`)

**요청**: `multipart/form-data`

| 파트 | 필수 | 규칙 |
|---|---|---|
| `categoryId` · `title` · `content` | ✅ | 5번과 같다 |
| **`deleteAttachmentIds`** | — | **지울 기존 첨부의 id 목록** |
| `files` | — | 새로 추가할 파일 |

| 응답 | 조건 | `code` | AC |
|---|---|---|---|
| **200** | 성공. **등록자·등록일시는 바뀌지 않는다** | — | `AC-51` `AC-55` |
| 401 | 미인증 | `AUTH_REQUIRED` | |
| **403** | **타인의 글** (`ADMIN` 포함) | `POST_NOT_OWNER` | `AC-52` `AC-53` `AC-54` |
| 404 | 없는·삭제된 글 | `POST_NOT_FOUND` | |

| 400 | 그 밖의 검증 | 코드 표 | `AC-38`~`AC-47` |

### ★ 왜 "유지 목록"이 아니라 "삭제 목록"인가 — 이 계약에서 가장 틀리기 쉬운 한 줄

| | 삭제 목록(`deleteAttachmentIds`) — **채택** | 유지 목록(`keepAttachmentIds`) — 기각 |
|---|---|---|
| 최종 상태 | (현재 첨부 − 삭제 목록) + 새 파일 | (현재 첨부 ∩ 유지 목록) + 새 파일 |
| **화면이 모르는 첨부가 있을 때** | **살아남는다** | **조용히 삭제된다** |

**판단 12가 낙관적 잠금을 넣지 않기로 했으므로**(같은 사람의 두 창), 화면이 폼을 연 뒤
다른 창에서 첨부가 추가되는 상황이 실재한다. 유지 목록 방식은 **그 첨부가 목록에 없다는
이유로 지워 버린다** — 사용자가 시키지 않은 삭제이고, **되돌릴 수 없다.**
삭제 목록 방식은 살려두고, **개수 초과면 `AC-56`대로 거부**한다.

**개수는 반드시 요청 시점의 실제 상태로 다시 센다**(`AC-56`·`AC-61`).
화면이 들고 온 옛 개수(4개)를 믿고 계산하면 **상한이 새 나간다.**
`4 − 2 + 3 = 5` 통과 / `4 + 2 = 6` 거부이며, **거부되면 아무 변경도 적용되지 않는다.**

### 403인가 404인가 — 의도적 판단

**403이다.** constitution 원칙 IV는 *"남의 **비공개** 리소스 요청은 404"* 인데
**자유게시판 글은 공개다** — `AC-26`·`AC-31`이 로그인 없이 목록과 상세를 허용했으므로
**존재 여부는 이미 모두에게 공개된 정보**이고 감출 대상이 없다.
404로 답하면 사용자는 *"글이 지워졌나"* 로 오해한다.
**006 비밀글은 반대이며 거기서는 404가 맞다**(판단 10).

## ★ 이 계약에서 가장 깨지기 쉬운 부분

### 1. 오류 코드를 하나로 뭉치는 것

**400 여덟 종의 상태코드가 전부 같다.** 조건 검증 실패를 공통 코드 하나로 던지면
`AC-3`·`AC-4`·`AC-6`·`AC-9`·`AC-18`이 **서로 구분되지 않는데도** 상태코드만 보는 테스트는
**전부 통과한다.** 사용자는 무엇이 잘못됐는지 알 수 없고, 화면은 안내 문구를 고를 수 없다.

| | 대응 |
|---|---|
| 1 | **위 코드 표가 단일 진실**이다. 001이 `detail`까지 한 곳(`ErrorCode`)에 모은 것과 같은 형태로 002 코드를 추가한다 |
| 2 | **모든 테스트가 `code`를 단언한다.** 상태코드만 보는 테스트를 쓰지 않는다 — 그러면 뭉쳐진 구현이 반드시 실패한다 |
| 3 | ⚠️ **`POST_CATEGORY_NOT_SELECTABLE`만 예외로 둘로 나누지 않았다**(`AC-42` 비활성 / `AC-43` 타 게시판). **의도적이다** — 둘 다 *"이 게시판에서 지금 고를 수 없는 분류"* 라는 하나의 사실이고, 나누면 **어느 게시판에 어떤 분류가 있는지**를 응답이 알려준다 |

### 2. 첨부 응답 헤더가 **한 세트**라는 것

4번 엔드포인트의 헤더 4종은 **하나라도 빠지면 방어가 뚫린다.**
그런데 **빠져도 정상 동작으로 보인다** — 파일은 어차피 내려받아지기 때문이다.

- `AC-32`(다운로드 지정)와 `AC-33`(형식 추측 금지)을 **한 테스트로 뭉치지 않는다.**
  한 겹이 빠져도 드러나야 한다.
- **`Content-Type`을 업로드 때 클라이언트가 보낸 값으로 채우는 것**이 가장 조용한 실패다.
  서버가 **확장자에서 정한 값만** 쓴다.
- 한글 파일명은 **`filename*`(RFC 5987)** 없이는 깨진다. `AC-35`의 예시가
  `보고서 최종(1).zip`(한글 + 공백 + 괄호)인 것은 **세 가지 함정을 한 번에** 밟기 위해서다.

### 3. 글 번호와 총건수가 **같은 조건·같은 시점**에서 나와야 한다

`number = totalElements − (page × size) − 행 인덱스` 다.
`totalElements`가 **목록 본문과 다른 조건**(예: 기간 필터를 빠뜨린 COUNT)에서 나오거나
**다른 시점**에 계산되면, 번호가 조용히 어긋난다 — **화면은 정상으로 보인다.**

- 두 질의는 **같은 검색 조건**에서 나와야 한다.
- ⚠️ **분모가 "결과 총건수"인지 "게시판 전체 건수"인지**는 판단 3이 **결과 총건수**로 정했고
  이 계약이 그것을 따른다. **003·005·006이 그대로 물려받으므로 한쪽으로 닫혀 있어야** 한다
  → `plan.md` 미해결 5.

### 4. `AC-30`과 `AC-59`의 응답이 **완전히 같아야** 한다

없는 글과 삭제된 글이 **각각 404여도 `code`나 `detail`이 다를 수 있다.**
다르면 *"이 번호에 글이 있었다"* 는 사실이 남는다.
→ **두 응답을 서로 비교하는 테스트를 따로 둔다.** 각각을 검증하는 테스트만으로는 부족하다
(001의 `AC-2`·`AC-3` 처리와 같은 종류).

### 5. 관리자 예외가 **한 곳에만** 있다

`ADMIN`은 **댓글 삭제(9번)만** 가능하고 **글 수정·삭제(6·7번)는 불가**하다.
권한 검사를 *"본인 또는 관리자"* 라는 **한 벌의 유틸리티**로 만들면
**`AC-54`가 조용히 깨진다** — 관리자가 남의 글 본문을 고칠 수 있게 되고,
**작성자가 쓰지 않은 내용이 그의 이름으로 남는다.**
→ 판정 함수를 **글용과 댓글용으로 나눈다.** `AC-54`와 `AC-69`가 **대비되는 쌍**으로 테스트된다.

## 프론트 계약 (화면이 책임지는 것)

| | 요구 | AC |
|---|---|---|
| **검색조건을 주소(URL)에 담는다** | 뒤로가기·새로고침·링크 공유가 전부 성립한다. 서버 세션이나 전역 상태에 넣으면 **탭 두 개가 서로 덮어쓴다**(판단 7) | `AC-23` `AC-24` |
| **개씩보기·정렬은 즉시 반영** | 검색 버튼을 누르지 않는다. **다른 조건을 유지한 채** 다시 조회한다 | `AC-11` |
| **상세→목록, 취소→목록에서 조건 유지** | 기간·분류·검색어·개씩보기·정렬 기준·정렬 방향·**페이지 번호** 7가지 전부 | `AC-23` `AC-24` |
| **확인 대화상자** | 작성 취소 `"작성을 취소하시겠습니까?"` · 삭제 `"정말로 삭제 하시겠습니까"` | `AC-50` `AC-62` |
| **버튼 숨김은 검증이 아니다** | 수정·삭제 버튼을 본인에게만 보이되, **그것을 권한 검증으로 여기지 않는다.** 서버가 6·7·9에서 다시 확인한다 | `AC-53` `AC-68` |
| **미인증 시 목적지 복귀** | 001 `FR-020`·`FR-035`를 그대로 쓴다. **목적지는 같은 출처의 상대 경로만.** 002는 목적지만 제공한다 | `AC-37` |
| **빈 목록일 때 적용된 기간을 알린다** | 기본 1개월이라 *"게시판이 비었다"* 로 보이는 상황이 정상 사용 중에 생긴다. `appliedCriteria`를 써서 *"최근 1개월 내 등록된 글이 없습니다"* 처럼 보여준다 | `AC-1` · Edge Cases |
| **인라인 미리보기를 만들지 않는다** | 첨부는 항상 다운로드다. 이미지 태그로 첨부 URL을 직접 참조하는 화면을 만들면 `AC-32`의 의도가 화면 쪽에서 무너진다 | `AC-32` |

> **`AC-50`·`AC-62`(확인 대화상자)에는 자동 테스트가 배정되지 않았다** —
> E2E 예산에서 깎였고 프론트 컴포넌트 테스트 레벨이 전략에 없다.
> **9.5 기능 QA가 판정**하며, 레벨이 생기면 승격한다(`plan.md` 「E2E 예산」·미해결 1).
